    802.1X Wired Authentication mit FreeRADIUS AAA

    Einführung

    802.1X ist ein Standard für Port-basierte Netzwerkzugangskontrolle (Network Access Control, NAC). Bevor ein Endgerät Zugriff auf das Netzwerk erhält, muss es sich gegenüber einem Authenticator authentifizieren. Der Authenticator leitet die Authentifizierungsdaten an einen RADIUS-Server weiter. Der eigentliche Authentifizierungsmechanismus erfolgt über EAP (Extensible Authentication Protocol). Das Lab basiert auf FreeRADIUS als Authentication Server und hostapd im Wired-Modus als Authenticator.

    In dieser Übung wird ein vollständiger 802.1X-Wired-Aufbau ohne Hardware-Switch realisiert. Die Teilnehmer analysieren den EAP-Prozess und vergleichen die Verfahren EAP-MD5 und PEAP.

    Ziele

    • Aufbau einer funktionierenden 802.1X-Umgebung

    • Verständnis der Rollen Supplicant, Authenticator und Authentication Server

    • Analyse von EAPOL- und RADIUS-Kommunikation

    • Interpretation des Authentifizierungsprozesses

    • Vorbereitung auf moderne EAP-Verfahren wie PEAP oder EAP-TLS

    Kompetenzzuordnung

    Schichtenmodelle und Protokolle

    • das TCP/IP-Modell und das OSI-Modell gegeneinander abgrenzen
    • aufgrund von Anforderungsspezifikationen an lokale Netze Kommunikationsmodelle für Weitverkehrsnetze erarbeiten

    Übertragungsmedien und Netztopologien

    • bei gegebenen Anforderungen an Netzwerke Lösungskonzepte zur Realisierung von Topologien
      erarbeiten
    • eine WLAN basierende Infrastruktur erstellen.

    Switching und Routing

    • ein SOHO-Netzwerk installieren
    • Switching- und Routingkonzepte in SOHO-Netzwerken umsetzen.

    Voraussetzungen

    • aktuelle Ubuntu Installation

    Detaillierte Aufgabenbeschreibung

    In diesem Lab übernimmt ein Ubuntu-Server sowohl die Rolle des Authenticators (hostapd) als auch des Authentication Servers (FreeRADIUS). Ein zweiter Ubuntu-Rechner fungiert als Supplicant und authentifiziert sich über 802.1X am Netzwerk. Die Verbindung zwischen beiden Systemen erfolgt über eine direkte Ethernet-Verbindung.

    Hinweis: EAP-MD5 wird heute nicht mehr als Stand der Technik angesehen, da keine Verschlüsselung und keine Authentifizierung des Servers erfolgt. Es eignet sich jedoch sehr gut, um die grundlegenden Abläufe von 802.1X, EAP und RADIUS zu verstehen.

    Das Lab bildet die wesentlichen Komponenten einer produktiven 802.1X-Umgebung nach. In einem realen Netzwerk werden die Rollen jedoch auf unterschiedliche Geräte verteilt:

    +---------------------+     +----------+----------+     +----------+----------+
| PC / Notebook       |     | Access Switch       |     | FreeRADIUS /        |
| Supplicant          | --- | Authenticator       | --- | NPS / ISE           |
| Auth. Server        |     |                     |     | Auth. Server        |
+----------+----------+     +----------+----------+     +----------+----------+

    Der Client sendet seine Anmeldedaten an den Switch. Der Switch überprüft die Daten nicht selbst, sondern leitet die EAP-Nachrichten über RADIUS an den Authentication Server weiter. Erst nachdem dieser die Anmeldung bestätigt (Access-Accept), wird der Netzwerkport freigeschaltet und der Client erhält Zugriff auf das Netzwerk.

    Im Lab übernimmt hostapd die Rolle des Access-Switches, während FreeRADIUS den zentralen Authentication Server darstellt. Dadurch kann der vollständige 802.1X-Ablauf ohne spezielle Netzwerkhardware nachvollzogen werden.

    Aufgabe Grundkompetenz:

    Teil 1 – FreeRADIUS konfigurieren

    In diesem Teil wird der zentrale Authentication Server eingerichtet. FreeRADIUS übernimmt die Überprüfung von Benutzername und Passwort und entscheidet, ob ein Client Netzwerkzugang erhält.

    Installiere die folgenden Pakete:

    sudo apt update
sudo apt install -y freeradius freeradius-utils hostapd tcpdump

    Benutzer anlegen

    Datei öffnen:

    sudo nano /etc/freeradius/3.0/users

    Benutzer hinzufügen:

    <dein Vorname> Cleartext-Password := "Passw0rd!"

    Authenticator registrieren

    Datei öffnen:

    sudo nano /etc/freeradius/3.0/clients.conf

    Eintrag ergänzen (Achtung, je nach Version ist dieser Eintrag bereits vorhanden):

    client localhost {
    ipaddr = 127.0.0.1
    secret = testing 123
}

    Ersetze das Secret durch dein gewähltes Passwort.

    EAP-MD5 konfigurieren

    Datei öffnen:

    sudo nano /etc/freeradius/3.0/mods-enabled/eap

    Kontrollieren:

    default_eap_type = md5

    FreeRADIUS starten

    sudo systemctl restart freeradius
sudo systemctl status freeradius

    Im Debug Modus

    sudo freeradius -X

    Überprüfe:

    sudo systemctl status freeradius

    Der Dienst muss den Status active (running) besitzen.

    Teil 2 – Authenticator konfigurieren

    In diesem Teil wird hostapd als 802.1X-Authenticator eingerichtet. Der Authenticator befindet sich zwischen Client und FreeRADIUS und leitet die EAP-Nachrichten an den RADIUS-Server weiter.

    hostapd (Host Access Point Daemon) wird normalerweise verwendet, um einen Linux-Rechner als WLAN Access Point zu betreiben und dabei Funktionen wie WPA2/WPA3 und 802.1X bereitzustellen.

    In dieser Übung verwenden wir hostapd jedoch nicht als WLAN Access Point, sondern im sogenannten Wired-Modus (driver=wired). Dadurch übernimmt hostapd die Rolle eines 802.1X-Authenticators für kabelgebundene Netzwerkverbindungen.

    In einer realen Unternehmensumgebung würde diese Aufgabe normalerweise ein 802.1X-fähiger Switch übernehmen. Da im Lab kein entsprechender Switch vorhanden ist, simuliert hostapd diese Funktion softwarebasiert.

    hostapd Konfiguration

    Datei erstellen:

    sudo nano /etc/hostapd/hostapd.conf

    Inhalt:

    interface=eth0
driver=wired

ieee8021x=1

auth_server_addr=127.0.0.1
auth_server_port=1812
auth_server_shared_secret=testing123

logger_stdout=-1
logger_stdout_level=1
logger_syslog=-1
logger_syslog_level=1

    hostapd starten

    sudo hostapd /etc/hostapd/hostapd.conf

    Im Debug Modus:

    sudo hostapd -dd /etc/hostapd/hostapd.conf

    Es dürfen keine Fehlermeldungen erscheinen.

    Teil 3 – Supplicant konfigurieren

    Der Supplicant repräsentiert den Client. Er beantwortet die Authentifizierungsanfragen des Authenticators und stellt die Zugangsdaten bereit.

    Installiere:

    sudo apt update
sudo apt install -y wpasupplicant

    Konfiguration erstellen

    Datei:

    sudo nano /etc/wpa_supplicant/wired.conf

    Inhalt:

    ctrl_interface=/run/wpa_supplicant
network={
    key_mgmt=IEEE8021X
    eap=MD5
    identity="alice"
    password="Passw0rd!"
}

    Supplicant starten

    sudo wpa_supplicant -i eth0 -D wired -c /etc/wpa_supplicant/wired.conf

    Im Hintergrund:

    sudo wpa_supplicant -i eth0 -D wired -c /etc/wpa_supplicant/wired.conf -B

    Teil 4 – Authentifizierungsstatus prüfen

    In diesem Teil wird überprüft, ob die Authentifizierung erfolgreich abgeschlossen wurde.

    Status anzeigen:

    sudo wpa_cli status

    Die erfolgreich abgeschlossene Authentifizierung erkennt man an folgenden Zuständen:

    suppPortStatus=Authorized
EAP state=SUCCESS
Supplicant PAE state=AUTHENTICATED

    Teil 5 – EAPOL analysieren

    802.1X verwendet EAP over LAN (EAPOL) zwischen Supplicant und Authenticator. In diesem Teil wird der Layer-2-Authentifizierungsverkehr untersucht.

    Mitschnitt starten:

    sudo tcpdump -i eth0 -nn ether proto 0x888e

    Führe anschließend eine Anmeldung durch.

    Beobachtung

    Notiere die Reihenfolge der beobachteten Nachrichten.

    Beobachtbare Schritte:

    EAPOL Start
EAP Request Identity
EAP Response Identity
EAP Request MD5 Challenge
EAP Response MD5 Challenge
EAP Success

    Beantworte:

    • Wer sendet das erste Paket der Authentifizierung?
    • Welche Aufgabe hat das Paket „EAPOL Start“?
    • Warum fordert der Authenticator zunächst die Identity an?
    • Welche Informationen werden im „Response Identity“ übermittelt?
    • Wer erzeugt die MD5-Challenge?
    • Wer beantwortet die MD5-Challenge?
    • Wie erkennt der Client, dass die Authentifizierung erfolgreich war?
    • Welches Paket markiert das Ende des EAP-Austauschs?

    Erstelle eine Ablaufskizze.

    Teil 6 – RADIUS analysieren

    Der Authenticator verarbeitet die Zugangsdaten nicht selbst, sondern leitet sie per RADIUS an FreeRADIUS weiter.

    In diesem Teil wird die Kommunikation zwischen Authenticator und RADIUS-Server untersucht.

    Mitschnitt starten:

    sudo tcpdump -i lo -nn port 1812

    Anschließend die Authentifizierung erneut durchführen.

    Dokumentiere die Reihenfolge der RADIUS-Pakete.

    Beobachtbare Schritte:

    Access-Request
Access-Challenge
Access-Request
Access-Accept

    Beantworte:

    • Welche Aufgabe hat ein Access-Request?
    • Welche Informationen werden im Access-Request transportiert?
    • Warum sendet FreeRADIUS ein Access-Challenge?
    • Welche EAP-Nachricht entspricht dem ersten Access-Challenge?
    • Welche EAP-Nachricht entspricht dem zweiten Access-Request?
    • Warum sendet der Authenticator mehrere Access-Requests?
    • Welche Bedeutung hat ein Access-Accept?
    • Wer entscheidet letztendlich über den Netzwerkzugang?
    • Welche Aufgabe übernimmt der Authenticator nach einem Access-Accept?
    • Welche Aufgabe hätte ein Access-Reject?

    Erstelle eine zweite Ablaufskizze.

    Teil 7 – Authentifizierungsablauf

    Erkläre den vollständigen Authentifizierungsablauf in eigenen Worten, der sowohl den EAPOL als auch den RADIUS Anteil enthält.

    Die Beschreibung soll so detailliert sein, dass ein Mitschüler den kompletten Ablauf allein anhand deiner Erklärung nachvollziehen kann.

    Erstelle eine Skizze, welche zeigt:

    • welche Geräte beteiligt sind,
    • welche Rolle die Geräte übernehmen,
    • welche Nachrichten zwischen den Geräten ausgetauscht werden.

    Teil 8 – Accounting aktivieren und analysieren

    Bisher wurden in der Übung die Bereiche Authentication und Authorization betrachtet.

    Authentication → Wer bist du?

    Authorization → Darfst du auf das Netzwerk zugreifen?

    Unternehmen möchten häufig zusätzlich nachvollziehen können:

    • Wer sich angemeldet hat?
    • Wann die Anmeldung erfolgte?
    • Wie lange die Verbindung bestand?
    • Wann die Verbindung beendet wurde?

    Diese Informationen werden als Accounting bezeichnet.

    In diesem Teil wird untersucht, wie ein RADIUS-Server Accounting-Informationen entgegennehmen und speichern kann.

    Accounting auf dem Authenticator aktivieren

    Bearbeite die Datei:

    sudo nano /etc/hostapd/hostapd.conf

    Ergänze folgende Zeilen:

    acct_server_addr=127.0.0.1
acct_server_port=1813
acct_server_shared_secret=testing123

    Starte hostapd neu.

    Accounting-Mitschnitt starten

    Auf dem Server:

    sudo tcpdump -i lo -nn port 1813

    Führe eine erneute Authentifizierung durch.

    Während oder nach der Anmeldung sollten Accounting-Pakete sichtbar werden.

    Beispiel:

    Accounting-Request

    Prüfe auf dem FreeRADIUS-Server:

    sudo find /var/log/freeradius -type f

    Besonders interessant sind Dateien unter:

    /var/log/freeradius/radacct/

    Inhalt anzeigen:

    sudo less /var/log/freeradius/radacct/127.0.0.1/auth-detail-date

    Beantworte:

    • Wofür steht das dritte „A“ in AAA?
    • Welche Informationen werden durch Accounting erfasst?
    • Warum reicht Authentication allein für viele Unternehmen nicht aus?
    • Welche Vorteile bietet Accounting für Administratoren?
    • In welchen Bereichen außer 802.1X wird Accounting noch eingesetzt? Nenne mindestens drei Beispiele.

    Aufgabe Erweiterte Kompetenz:

    Im Grundlagenteil wurde EAP-MD5 verwendet, um den grundsätzlichen Ablauf einer 802.1X-Authentifizierung kennenzulernen. Dieses Verfahren wird heute nicht mehr produktiv eingesetzt, da weder die Identität des Servers überprüft noch die Anmeldedaten geschützt übertragen werden.

    Moderne 802.1X-Umgebungen verwenden meist PEAP oder EAP-TLS. Beide Verfahren nutzen TLS und Zertifikate. Dadurch wird die Authentifizierung wesentlich sicherer.

    In diesem Übungsteil wird die bestehende Umgebung auf PEAP-MSCHAPv2 umgestellt und anschließend mit EAP-MD5 verglichen.

    Teil 8 – FreeRADIUS auf PEAP umstellen

    PEAP benötigt ein Zertifikat auf dem RADIUS-Server. In diesem Teil werden die vorhandenen Zertifikate untersucht und ihre Aufgaben erklärt.

    Wechsle in das Zertifikatsverzeichnis:

    cd /etc/freeradius/3.0/certs

    Zeige die vorhandenen Dateien an.

    Identifiziere welche Zertifikate durch freeRADIUS im Standardsertup verwendet werden.

    Beantworte:

    • Welche Aufgabe hat die Datei ca.pem?
    • Welche Aufgabe hat die Datei server.pem?
    • Welche Aufgabe hat die Datei server.key?
    • Warum darf der private Schlüssel nicht an Clients weitergegeben werden?
    • Welche Datei muss ein Client erhalten, um das Serverzertifikat prüfen zu können?
    • Was könnte passieren, wenn der Client das Serverzertifikat nicht überprüft?

    Öffne die EAP-Konfiguration:

    sudo nano /etc/freeradius/3.0/mods-enabled/eap

    Ändere:

    default_eap_type = md5

    zu:

    default_eap_type = peap

    Prüfe anschließend die Zertifikatseinträge:

    private_key_file = /etc/freeradius/3.0/certs/server.key
certificate_file = /etc/freeradius/3.0/certs/server.pem
ca_file = /etc/freeradius/3.0/certs/ca.pem

    Speichere die Änderungen.

    FreeRADIUS neu starten

    sudo systemctl restart freeradius

    Teil 9 – PEAP am Client einrichten

    Der Client muss der ausstellenden Zertifizierungsstelle vertrauen, damit er die Identität des RADIUS-Servers überprüfen kann.

    Kopiere das CA-Zertifikat auf den Client.

    Beispiel:

    scp /etc/freeradius/3.0/certs/ca.pem student@CLIENT:/tmp

    Beantworte:

    • Warum wird nicht das Serverzertifikat, sondern das CA-Zertifikat auf den Client kopiert?
    • Welche Aufgabe übernimmt die Zertifizierungsstelle (CA)?
    • Wie kann der Client damit die Echtheit des Servers überprüfen?

    Der Supplicant wird nun so angepasst, dass die Authentifizierung über PEAP und MSCHAPv2 erfolgt.

    Bearbeite die Datei:

    sudo nano /etc/wpa_supplicant/wired.conf

    Inhalt:

    ctrl_interface=/run/wpa_supplicant
network={
    key_mgmt=IEEE8021X
    eap=PEAP
    identity="alice"
    password="Passw0rd!"
    phase2="auth=MSCHAPV2"
    ca_cert="/tmp/ca.pem"
}

    Supplicant neu starten

    sudo pkill wpa_supplicant
sudo wpa_supplicant -i eth0 -D wired -c /etc/wpa_supplicant/wired.conf

    Kontrolle:

    sudo wpa_cli status

    Dokumentiere:

    • suppPortStatus
    • EAP state
    • Supplicant PAE state

    Beantworte:

      1. Was hat sich gegenüber EAP-MD5 geändert?
    • Welche Aufgabe hat die Zeile ca_cert="/tmp/ca.pem"?

    Teil 10 – RADIUS-Kommunikation analysieren

    PEAP erzeugt deutlich mehr Nachrichten als EAP-MD5. Der Grund dafür soll anhand eines Mitschnitts nachvollzogen werden.

    Starten des Mitschnitts:

    sudo tcpdump -i lo -nn port 1812

    Anschließend den Supplicant neu starten oder die Authentifizierung erneut auslösen.

    Dokumentiere:
