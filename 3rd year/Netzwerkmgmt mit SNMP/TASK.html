    Modernes Netzwerkmanagement mit SNMPv3

    Einführung

    Das Simple Network Management Protocol (SNMP) ist eines der wichtigsten Protokolle zur Überwachung und Verwaltung von Netzwerkgeräten, Servern und IT-Infrastrukturen. Nahezu alle professionellen Netzwerkkomponenten – Router, Switches, Firewalls, Linux- und Windows-Server – stellen Betriebs- und Statusinformationen über SNMP bereit.

    In diesem Labor lernst du die Grundlagen und den praktischen Einsatz von SNMP anhand einer modernen Umgebung mit SNMPv3, grafischen Analysewerkzeugen sowie professionellen Monitoring-Lösungen kennen. Du untersuchst die Struktur von MIB-Dateien, analysieren OIDs, richtest einen SNMP-Agenten ein, führst Abfragen mit den Werkzeugen der Net-SNMP-Suite durch und überwachst Systeme über SNMP.

    Darüber hinaus werden ereignisgesteuerte Benachrichtigungen mittels SNMP-Traps und SNMP-Informs untersucht. Abschließend erfolgt die Integration eines SNMP-Geräts in ein professionelles Monitoring-System wie Zabbix, sowie eine Sicherheitsanalyse unterschiedlicher SNMP-Konfigurationen.

    Ziele

    • Details zum SNMP-Protokoll
    • MIB-Strukturen und OIDs interpretieren können.
    • MIB-Daten mittels snmpget, snmpwalk und snmptranslate abrufen.
    • Verwendung eines SNMP-Managers zum Abfragen eines SNMP-Agenten
    • Verwendung von SNMP zum Ermitteln der Netzwerkkonfiguration
    • Aufbau und Funktion von SNMP verstehen.
    • SNMP-Traps und Informs analysieren.
    • Sicherheitsrisiken von SNMPv1/v2c bewerten.
    • Netzwerkgeräte in moderne Monitoring-Systeme integrieren.

    Kompetenzzuordnung

    Bereich Schichtenmodelle und Protokolle

    • das TCP/IP-Modell und das OSI-Modell gegeneinander abgrenzen

    Bereich Übertragungsmedien und Netztopologien

    • bei gegebenen Anforderungen an Netzwerke Lösungskonzepte zur Realisierung von Topologien erarbeiten

    Voraussetzungen

    • Server_KN und Client_KN aus vorangegangenen Übungen sind lauffähig
    • NET-SNMP-Tools: Informationen zu den NET-SNMP-Softwaretools findest du unter http://net-snmp.sourceforge.net/. Lies insbesonders die folgenden Befehle, die in dieser Übung verwendet werden, im Abschnitt „Tutorial“:
    • snmpd
    • snmpget
    • snmpgetnext
    • snmpwalk
    • Lies dir ein kurzes SNMP Tutorial durch: An Introduction to SNMP (Simple Network Management Protocol) | DigitalOcean

    Teil 2 – Vorbereitungen

    Installation auf Server_KN und Client_KN.

    sudo apt update
sudo apt install snmp snmpd snmptrapd snmp-mibs-downloader

    Prüfe:

    snmpget --version
sudo ss -ulnp | grep 161

    Erwartet:

    0.0.0.0:161

    In der Konfiguration ist notwendig, dass die folgende Zeile in /etc/snmp/snmp.conf auskommentiert ist:

    # mibs :

    Wenn die Zeile aktiv wäre, dann würde Net-SNMP keine MIB-Dateien laden. Das führt typischerweise zu Fehlern wie:

    Unknown Object Identifier (Sub-id not found: (top) -> sysName)

    Setze auch eine Umgebungsvariable mit dem Pfad zu den MIBs:;

    export MIBDIRS=/usr/share/snmp/mibs:/usr/share/snmp/mibs/ietf:/usr/share/snmp/mibs/iana

    Du kannst dies dauerhaft in ~/.bashrc hinterlegen, indem du den export Befehl dort einfügst.

    Anschließend laden:

    source ~/.bashrc

    Prüfen:

    echo $MIBDIRS

    Teil 3 – MIBs und OIDs verstehen

    In diesem Abschnitt erfährst du, wie Objekte in MIB-Dateien verwaltet, definiert und organisiert werden.

    Auf den Linux-PCs werden die MIB-Dateien im Verzeichnis abgelegt:

    cd /usr/share/snmp/mibs

    Beim Start eines SNMP-Agenten werden die MIB-Dateien kompiliert und in eine Datenbank geladen. Jede MIB-Datei gibt einen Satz verwalteter Objekte an. Die Objekte werden nach dem SMI Format (Structure of Management Information) basierend auf ASN.1 (Abstract Syntax Notation One) spezifiziert:

    objektName OBJECT-TYPE
    SYNTAX      Datentyp
    MAX-ACCESS  read-only | read-write | not-accessible
    STATUS      current | deprecated | obsolete
    DESCRIPTION "Beschreibung des verwalteten Objekts."
    ::= { OID-Pfad }

    Untersuche folgende Dateien:

    SNMPv2-MIB
IF-MIB
IP-MIB
TCP-MIB
UDP-MIB
IP-FORWARD-MIB
INET-ADDRESS-MIB

    Bestimmen für die Objekte:

    • sysName
    • ipForwarding
    • icmp

    jeweils:

    1. Numerische OID
    2. Vollständige Beschreibung
    3. Datentyp
    4. Vorhandene Unterobjekte

    Hinweis: less und grep sind hilfreiche Tools

    Teil 4 – MIB Baum erkunden (smtptranslate)

    Mit dem Befehl snmptranslate kannst du die Struktur eines MIB-Baums erkunden. Der Befehl snmptranslate kann zwischen numerischer und textueller Darstellung von Objekten übersetzen.

    Führe auf localhost die folgenden Befehle aus und speichere die Ausgabe in einer Datei. Beschreibe die Funktion der einzelnen Befehlsaufrufe.

    snmptranslate .1.3.6.1.2.1.7.4
snmptranslate sysName
snmptranslate -IR icmp
snmptranslate -Tp TCP-MIB::tcp
snmptranslate -Tp IF-MIB::interfaces

    Beantworte die folgenden Fragen:

    • Welche Routing-Protokolle werden von SNMP erkannt (Hinweis: IP-FORWARD-MIB)?
    • Die Zustände einer TCP-Verbindung auflisten (Hinweis: TCP-MIB)?
    • Wie kann man mit snmptranslate den gesamten Baum (d. h. verwurzelt bei .iso) anzeigen?

    Teil 5 – SNMPv3-Agent einrichten

    In diesem Teil der Übung untersuchst du die Interaktionen zwischen einem SNMP-Agenten (Client_KN) und einem SNMP-Manager (Server_KN).

    Ein SNMP-Manager und ein SNMP-Agent kommunizieren über das SNMP-Protokoll. Die in dieser Übung verwendeten SNMP-Nachrichtentypen werden von allen drei SNMP-Versionen unterstützt. SNMPv2c und SNMPv3 bieten zusätzliche Nachrichtenformate und einen größeren Funktionsumfang.

    Mit Ausnahme von Trap-Nachrichten wird der Austausch in SNMP von einem SNMP-Manager initiiert, indem er eine Anfrage an einen SNMP-Agenten sendet. Der SNMP-Agent antwortet mit einer Antwortnachricht. Die Nachrichtentypen sind folgende:

    • Get-Anfrage: Fordert die Werte eines oder mehrerer Objekte von einem SNMP-Agenten an.
    • Get-Next-Anfrage: Fordert den Wert des nächsten Objekts gemäß einer lexikografischen Ordnung der OIDs an.
    • Set-Anfrage: Eine Anfrage zur Änderung des Werts eines oder mehrerer Objekte auf dem Agenten.
    • Get-Antwort: Wird vom SNMP-Agenten als Antwort auf eine Get-Anfrage, Get-Next-Anfrage oder Set-Anfrage gesendet.
    • Trap: Ein SNMP-Trap ist eine Benachrichtigung, die von einem SNMP-Agenten an einen SNMP-Manager gesendet wird und durch bestimmte Ereignisse auf dem Agenten ausgelöst wird.

    Die allgemeine Syntax der SNMP-Manager-Befehle der NET-SNMP-Software lautet wie folgt (Details in der Manpage):

    snmpcmd [-v Version] Agent -c Community Objekt-ID

    SNMPv3 Benutzer anlegen

    sudo systemctl stop snmpd
sudo net-snmp-create-v3-user -ro -a SHA -A AuthPass2026 -x AES -X PrivPass2026 snmpadmin

    Damit der Agent auf alle Interfaces hört muss noch eine Zeile in /etc/snmp/snmpd.conf angepasst werden.

    # agentaddress  127.0.0.1,[::1]
agentaddress udp:161

    Dienst neu starten:

    sudo systemctl restart snmpd

    Der Befehl lädt die Verwaltungsdatenbank mit den MIB-Dateien im Verzeichnis /usr/share/snmp/mibs und konfiguriert den Agenten mit der Datei /usr/share/snmp/snmpd.conf.

    SNMPGET (Client_KN)

    snmpget -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 1.3.6.1.2.1.1.5.0

    Beispiel:

    SNMPv2-MIB::sysName.0 = STRING: NB-WHOEVER

    Führen Sie die folgenden Befehle aus, um auf Skalarvariablen zuzugreifen und die Ausgabe zu protokollieren:

    snmpget -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 sysDescr.0
snmpget -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 udp.udpOutDatagrams.0
snmpget -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 udp.udpInDatagrams.0

    Beachten Sie das Suffix „.0“ am Ende der OID. Dieses Suffix verweist auf eine Instanziierung des referenzierten Objekts, die den Wert speichert. Dies wird als Variablen bezeichnet. Beispielsweise verweist 1.3.6.1.2.1.7.4.0 auf die Variable, die den Wert für das Objekt udp.udpOutDatagrams enthält.

    Variablen, die einen einzelnen Wert speichern, werden als Skalarvariablen bezeichnet. Besteht ein Objekt aus einer Sequenz von Werten, gibt das Suffix den Index in der Sequenz an. Beispielsweise bezieht sich interfaces.ifTable.ifEntry.ifDescr.2 auf den zweiten Eintrag der Wertefolge in interfaces.ifTable.ifEntry.ifDescr.

    Führen die folgenden Befehle aus, um auf nicht-skalare Variablen zuzugreifen:

    snmpget -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 interfaces.ifTable.ifEntry.ifDescr.1
snmpget -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 interfaces.ifTable.ifEntry.ifDescr.2

    Erhöhe den Index weiter, bis eine Fehlermeldung angezeigt wird. Beachte, was passiert, wenn du den Wert als Skalarwert abfragst, d. h. mit dem Suffix „.0“.

    Verwende den Befehl snmpget, um mehrere Objektwerte mit demselben Befehl abzufragen:

    snmpget -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 system.sysUpTime.0 system.sysName.0

    Erklären:

    • Bedeutung des Suffixes „.0“
    • Unterschiede zwischen skalaren und tabellarischen Objekten

    SNMPGETNEXT

    Der Befehl snmpgetnext ruft den Wert der nächsten Variablen bzw. das nächste Objekt im Baum ab.

    Verwenden Sie den Befehl snmpgetnext, um alle Objekte unter dem Knoten at (Address Translation) im MIB-Baum abzurufen. Das Objekt at definiert eine Gruppe von Objekten, die die ARP-Tabelle des lokalen Systems speichern. Beginnen Sie mit dem Befehl:

    snmpgetnext -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 at

    Wie geht es weiter?

    SNMPWALK

    Mit dem Befehl snmpwalk können die Werte aller Objekte unter einem bestimmten Ort im MIB-Objekthierarchiebaum abgerufen werden. Das Abrufen eines vollständigen Teilbaums wird als „MIB-Walking“ bezeichnet. Verwende snmpwalk, um die Werte aller Objekte unter den Knoten system und interfaces zu erhalten.

    snmpwalk -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 system
snmpwalk -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 interfaces
snmpwalk -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10 IP-FORWARD-MIB::ipForward

    Erkläre die Struktur der Hierarchie.

    Dokumentiere:

    • Anzahl der Interfaces
    • Interface-Namen
    • Routingeinträge

    Teil 6 – MIB-Analyse mit SNMPB (SNMP Browser)

    Abhängig von der Distribution:

    sudo apt install snmpb

    Falls das Paket nicht verfügbar ist, kann die aktuelle Version von SourceForge heruntergeladen werden: https://sourceforge.net/projects/snmpb/

    SNMPv3 Verbindung konfigurieren

    Options - Manage Agent Profiles ...

    Konfiguriere

    Host: localhost
Version: SNMPv3
User: snmpadmin
Security Level: authPriv
Authentication: SHA
Authentication Password: AuthPass2026
Privacy Protocol: AES-128
Privacy Password: PrivPass2026

    Führe folgende Tätigkeiten aus:

    • Analyse eines skalaren Objekts
    • Analyse einer Tabelle
    • Untersuchung der Routing-MIB (IP-FORWARD-MIB)
      • Welche Routinginformationen sind verfügbar?
      • Welche Routing-Protokolle werden unterstützt?
      • Wie werden Next-Hop-Informationen dargestellt?
    • TCP-Verbindungen analysieren (TCP-MIB)`
      • tcpConnTable
      • tcpConnectionTable
      • Bestimme die möglichen TCP-Zustände

    Ein Netzwerkadministrator kann den SNMP-Manager verwenden, um den Status von TCP-Verbindungen auf entfernten Hosts zu überwachen, auf denen ein SNMP-Agent ausgeführt wird. Die gesammelten Informationen können genutzt werden, um die Aktivitäten auf entfernten Systemen zu überwachen.

    1. Stelle eine SSH-Sitzung zu Server_KN her
    2. Frage den TCP-Teil der MIB des Hosts ab, zu dem du eine SSH-Verbindung hergestellt hast
    3. Speichere die Ausgabe in einer Datei.
    4. Schließe die SSH-Sitzung(en).

    Suche in der gespeicherten Ausgabe nach Einträgen, die sich auf die SSH-Sitzungen beziehen. Wie können diese Informationen von einem Netzwerkadministrator genutzt werden?

    Teil 7 – SNMP-Traps

    Damit snmptrapd SNMPv3-Traps akzeptiert:

    sudo nano /etc/snmp/snmptrapd.conf

    Eintragen auf Server_KN:

    createUser snmpadmin SHA AuthPass2026 AES PrivPass2026
authUser log,execute,net snmpadmin

    sudo systemctl restart snmptrapd

    oder für den Test:

    sudo snmptrapd -f -Lo

    Test-Trap senden (Client_KN):

    snmptrap -v3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 localhost SNMPv2-MIB::coldStart

    Was is der Unterschied zwischen:

    • coldStart
    • linkUp
    • linkDown

    In /etc/snmp/snmpd.conf auf Client_KN können bestimmte Benachrichtigungen aktiviert werden.

    Beispiel:

    linkUpDownNotifications yes

    Dadurch erzeugt Net-SNMP bei Interface-Statusänderungen: linkDown, linkUp, ... Traps.

    Anschließend Empfänger definieren:

    trapsess -v 3 -u snmpadmin -l authPriv -a SHA -A AuthPass2026 -x AES -X PrivPass2026 192.168.<KN>.10

    Danach:

    sudo systemctl restart snmpd

    Schnittstelle deaktivieren:

    sudo ip link set eth0 down

    Aktivieren:

    sudo ip link set eth0 up

    Wenn die Benachrichtigungen aktiviert sind, sollte snmptrapd Meldungen ähnlich zu

    IF-MIB::linkDown
IF-MIB::linkUp

    anzeigen.

    Teil 13 – Mail versenden

    In diesem Teil wird ein SNMP-Trap nicht nur protokolliert, sondern automatisch verarbeitet. Beim Empfang eines bestimmten Traps soll ein Skript ausgeführt werden, das eine E-Mail an den Netzwerkadministrator versendet.

    Der Handler soll abhängig vom Trap-Typ unterschiedliche Betreffzeilen erzeugen.

    Beispiel:

    linkDown  → Kritischer Netzwerkalarm
linkUp    → Netzwerkverbindung wiederhergestellt
coldStart → Gerät neu gestartet

    Dazu soll ein Bash Trap-Handler-Skript erzeugt werden.

    sudo nano /usr/local/bin/snmptrap_mail.sh
sudo chmod +x /usr/local/bin/snmptrap_mail.sh
