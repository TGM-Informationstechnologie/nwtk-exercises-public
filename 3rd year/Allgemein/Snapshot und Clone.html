    VMware Workstation Pro: Klonen und Snapshots

    In Test-, Entwicklungs- und Schulungsumgebungen ist es häufig notwendig, virtuelle Maschinen schnell bereitzustellen, verschiedene Konfigurationen auszuprobieren und jederzeit auf einen bekannten funktionierenden Zustand zurückkehren zu können.

    VMware Workstation Pro stellt hierfür zwei zentrale Funktionen bereit:

    • Snapshots (Momentaufnahmen)
    • Klone (Kopien virtueller Maschinen)

    Diese Referenz erläutert die Unterschiede, Einsatzszenarien sowie die praktische Verwendung beider Funktionen.

    1. Grundlagen

    1.1 Was ist ein Snapshot?

    Ein Snapshot ist eine Momentaufnahme des Zustands einer virtuellen Maschine zu einem bestimmten Zeitpunkt.

    Ein Snapshot speichert:

    • den Zustand der virtuellen Festplatten
    • Konfigurationsänderungen
    • optional den aktuellen Arbeitsspeicherinhalt (wenn die VM eingeschaltet ist)

    Dadurch kann die virtuelle Maschine später exakt auf diesen Zustand zurückgesetzt werden.

    Typische Anwendungsfälle

    • Vor Softwareinstallationen
    • Vor Betriebssystemupdates
    • Vor Konfigurationsänderungen
    • Vor Tests mit unbekanntem Ausgang
    • Für Schulungs- und Demonstrationsumgebungen

    Vorteile

    • Schnelles Erstellen
    • Schnelles Zurücksetzen
    • Mehrere Entwicklungsstände möglich
    • Gute Absicherung vor risikobehafteten Änderungen

    1.2 Was ist ein Klon?

    Ein Klon ist eine Kopie einer bestehenden virtuellen Maschine.

    Dadurch kann aus einer bereits vorbereiteten VM schnell eine weitere VM mit identischer Grundkonfiguration erstellt werden.

    Nach dem Klonen müssen in der Regel nur noch systemspezifische Eigenschaften angepasst werden, beispielsweise:

    • Hostname
    • IP-Adresse
    • Domänenmitgliedschaft
    • Benutzerkonfiguration

    Typische Anwendungsfälle

    • Testumgebungen
    • Mehrere identische Server
    • Schulungsumgebungen
    • Softwaretests
    • Labors und Entwicklungssysteme

    1.3 Snapshots vs. Klone

    Snapshot Klon
    Speichert einen Zustand Erstellt eine neue VM
    Gehört zur ursprünglichen VM Eigenständige VM
    Benötigt wenig Speicherplatz Benötigt mehr Speicherplatz
    Ideal zum Zurücksetzen Ideal zum Vervielfältigen
    Keine neue VM Zusätzliche VM

    2. Klontypen

    VMware Workstation unterstützt zwei Arten von Klonen.

    2.1 Linked Clone

    Ein Linked Clone speichert nur die Änderungen gegenüber der Ausgangs-VM.

    Eigenschaften

    • Sehr schnell erstellt
    • Minimaler Speicherbedarf
    • Abhängig von der Original-VM
    • Nicht vollständig eigenständig

    Nachteile

    Wird die Original-VM beschädigt oder gelöscht, kann auch der Linked Clone unbrauchbar werden.

    Geeignet für

    • Temporäre Testsysteme
    • Entwicklung
    • Schulungen
    • Labors

    2.2 Full Clone

    Ein Full Clone ist eine vollständige Kopie der virtuellen Maschine.

    Eigenschaften

    • Vollständig unabhängig
    • Keine Abhängigkeit zur Original-VM
    • Höherer Speicherbedarf
    • Längere Erstellungszeit

    Vorteile

    • Kann auf andere Systeme kopiert werden
    • Höchste Flexibilität
    • Für produktionsnahe Testumgebungen geeignet

    Speicherbedarf

    Ein Full Clone benötigt ungefähr denselben Speicherplatz wie die Quelldateien der ursprünglichen VM.

    Beispiel:

    • VM-Größe: 60 GB
    • Benötigter zusätzlicher Speicherplatz: mindestens 60 GB

    3. Arbeiten mit Snapshots

    Snapshots können unabhängig davon erstellt werden, ob die virtuelle Maschine:

    • eingeschaltet
    • pausiert
    • ausgeschaltet

    ist.

    Ist die virtuelle Maschine eingeschaltet, wird zusätzlich der aktuelle Arbeitsspeicherzustand gespeichert. Dadurch kann später exakt derselbe Betriebszustand wiederhergestellt werden.

    3.1 Snapshot erstellen

    Virtuelle Maschine auswählen.

    VM → Snapshot → Take Snapshot

    Anschließend:

    1. Namen vergeben
    2. Beschreibung eintragen
    3. Snapshot erstellen

    Empfehlung

    Immer eine aussagekräftige Beschreibung hinterlegen. Dies erleichtert die spätere Identifikation erheblich.

    Nach dem Start der Snapshot-Erstellung erscheint ein Fortschrittsbalken.

    Obwohl die VM währenddessen weiter genutzt werden kann, ist häufig mit folgenden Effekten zu rechnen:

    • reduzierte Performance
    • verzögerte Reaktionen
    • erhöhte Festplattenaktivität

    Daher empfiehlt es sich, die Erstellung vollständig abzuwarten.

    Speicherort der Snapshot-Dateien

    Snapshot-Dateien werden im Verzeichnis der virtuellen Maschine gespeichert.

    Für jede virtuelle Festplatte (VMDK) erzeugt VMware entsprechende Snapshot-Dateien.

    Diese Dateien enthalten nicht die komplette Festplatte, sondern nur die Änderungen seit dem letzten Snapshot.

    Dadurch bleiben Snapshot-Dateien in der Regel deutlich kleiner als die eigentlichen VMDK-Dateien.

    3.2 Snapshot Manager verwenden

    Der Snapshot Manager ermöglicht die Verwaltung aller vorhandenen Snapshots.

    Aufruf:

    VM → Snapshot → Snapshot Manager

    Der Snapshot Manager ermöglicht:

    • Anzeigen aller Snapshots
    • Rückkehr zu einem beliebigen Snapshot
    • Verzweigungen von Entwicklungsständen
    • Löschen von Snapshots
    • Erstellen von Klonen aus Snapshots

    3.3 Auf einen Snapshot zurücksetzen

    1. Snapshot Manager öffnen
    2. Snapshot auswählen
    3. Wiederherstellen (Restore)

    Die VM wird anschließend genau auf den Zustand des gewählten Snapshots zurückgesetzt.

    4. Arbeiten mit Klonen

    Vor dem Klonen muss die virtuelle Maschine heruntergefahren sein.

    Während des Klonvorgangs dürfen die Dateien der VM nicht verändert werden.

    Da Windows- und Linux-Dateisysteme gleichzeitige Änderungen an denselben VM-Dateien typischerweise nicht erlauben, verlangt VMware Workstation eine ausgeschaltete VM.

    4.1. Klon über den Clone Wizard erstellen

    Schritt 1: Clone Wizard starten

    Pfad:

    VM → Manage → Clone

    Schritt 2: Quelle auswählen

    Zur Auswahl stehen:

    • Aktueller Zustand der VM: Klon der aktuellen virtuellen Maschine.
    • Snapshot: Klon eines vorhandenen Snapshots.

    Dies ist besonders nützlich, wenn mehrere Testsysteme von derselben Ausgangsbasis erstellt werden sollen.

    Schritt 3: Klontyp auswählen

    Auswahl zwischen:

    • Linked Clone
    • Full Clone

    Schritt 4: Name und Speicherort

    Festlegen von:

    • VM-Name
    • Speicherort auf dem Hostsystem

    Schritt 5: Klon erstellen

    Nach Abschluss des Assistenten erscheint die neue VM in der VMware-Bibliothek.

    Sie kann anschließend wie jede andere virtuelle Maschine:

    • gestartet
    • konfiguriert
    • geklont
    • gesichert
    • mit Snapshots versehen

    werden.

    4.2. Klon direkt aus dem Snapshot Manager erstellen

    Alternativ kann ein Klon unmittelbar aus einem Snapshot erzeugt werden.

    Vorgehensweise:

    1. Snapshot Manager öffnen
    2. Gewünschten Snapshot auswählen
    3. Clone auswählen
    4. Assistenten durchlaufen

    Vorteil: Der gewünschte Ausgangszustand kann direkt gewählt werden, ohne die VM zunächst auf diesen Zustand zurücksetzen zu müssen.

    Best Practices

    • Vor größeren Änderungen erstellen
    • Aussagekräftige Beschreibungen verwenden
    • Regelmäßig nicht mehr benötigte Snapshots entfernen
    • Nicht als langfristige Backup-Lösung verwenden
