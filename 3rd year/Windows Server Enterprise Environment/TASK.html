    Windows Enterprise Umgebung

    Einführung

    In dieser Übung baust du eine einfache, aber realitätsnahe Windows-Unternehmensumgebung auf. Dabei orientierst du dich an klassischen Unternehmensnetzwerken und an einem Windows-Server-Homelab-Szenario mit Domain Controller, DNS, DHCP, Fileserver und einem eingebundenen Client. Die Übung basiert auf bestehenden Unterrichtsunterlagen sowie einem aktuellen Homelab-Beispiel, das typische Windows-Server-Rollen praxisnah kombiniert.

    Hinweis: Gruppenrichtlinien (GPOs) sind bewusst nicht Bestandteil dieser Übung und werden in einer anschließenden Übung behandelt.

    Ziele

    • Windows Server installieren und grundlegend konfigurieren
    • einen Domain Controller einrichten
    • Active Directory Domain Services (AD DS) konfigurieren
    • DNS als Bestandteil einer Active-Directory-Umgebung einsetzen
    • Benutzerkonten in Active Directory anlegen
    • einen DHCP-Server konfigurieren
    • einen Fileserver bereitstellen und Freigaben erstellen
    • einen Windows-Client in die Domäne aufnehmen
    • die Funktion der bereitgestellten Dienste testen

    Kompetenzzuordnung

    Übertragungsmedien und Netztopologien

    • bei gegebenen Anforderungen an Netzwerke Lösungskonzepte zur Realisierung von Topologien erarbeiten
    • eine Kaufentscheidung für aktive Netzwerkkomponenten treffen

    Switching und Routing

    • Switching- und Routingkonzepte in SOHO-Netzwerken umsetzen
    • ein SOHO-Netzwerk installieren

    Voraussetzungen

    • VMware Workstation oder vergleichbare Virtualisierungslösung
    • Windows Server ISO
    • Windows 10 oder Windows 11 ISO

    Windows 10 beziehen

    Lade Windows 10 oder Windows 11 über Azure Dev Tools for Education herunter.

    Um auf Microsoft Azure zuzugreifen, navigiere hierher und melde dich mit deinem Schul-Account an. Wähle dann "Software" (Direktlink) und eine der Windows 10/11 Versionen. Es sollte rechts ein Panel mit Produktdetails und zwei Buttons erscheinen:

    • View Key: zeige den Produktschlüssel für Windows 10 an.
    • Generate URL: generiere einen begrenzt gültigen Download-Link für Windows 10/11.

    Notiere den Produktschlüssel.

    Verwende das ISO später für die Installation der VM PC01

    Windows Server beziehen

    Wie das Client Betriebssystem kannst du den Windows Server genauso über Azure Dev Tools for Education herunterladen.

    1. Melde dich bei Azure Dev Tools for Education an.
    2. Öffne den Bereich Software.
    3. Suche nach Windows Server 2022 oder 2025 Standard.
    4. Notiere den Produktschlüssel.
    5. Generiere einen Download-Link und lade das ISO-Image herunter.

    Detaillierte Aufgabenbeschreibung

    Die Firma TechSolutions GmbH ist ein kleines Unternehmen mit rund 20 Mitarbeitern. Die bestehende IT-Infrastruktur soll zentral verwaltet werden, damit Benutzerkonten, Computer und gemeinsame Dateien einfacher administriert werden können. Zu diesem Zweck wird eine Windows-Domäne aufgebaut, die zentrale Benutzerverwaltung über Active Directory bereitstellt. Zusätzlich sollen DNS, DHCP und ein Fileserver eingerichtet werden, damit die Arbeitsplatzrechner automatisch Netzwerkeinstellungen erhalten und gemeinsam auf Unternehmensdaten zugreifen können. Das Szenario orientiert sich an einer typischen kleinen Unternehmensumgebung und bildet die Grundlage für spätere Übungen zu Gruppenrichtlinien und zentralem Systemmanagement.

    Die folgende Infrastruktur soll aufgebaut werden:

    System Name IP Rolle
    Windows Server <INT>-DC01 192.168.<KN>.10 Domain Controller, DNS, DHCP
    Windows Server <INT>-FS01 192.168.<KN>.20 Fileserver
    Windows 10/11 <INT>-PC01 192.168.<KN>.100 - 200 (DHCP) Domänen-Client

    Verwende eine eigene Domäne:

    <INT>.local

    Aufgabe Grundkompetenz:

    Teil 1 – Domain Controller installieren

    Erstelle eine virtuelle Maschine mit folgenden Eigenschaften:

    • Betriebssystem: Windows Server 2022 Standard
    • Desktop Experience
    • Name: <INT>-DC01
    • 2 CPUs
    • mindestens 4 GB RAM
    • 2 Netzwerkkarten mit Netzwerkmodus Host-Only (Intern) und Bridged (Extern)

    Wähle bei der Installation die "Desktop Experience", also Windows Server inklusive GUI.

    Verwende folgende Anmeldedaten:

    Benutzer: Administrator
Passwort: Password1!

    Mache nach erfolgreicher Installation einen Snapshot.

    Grundkonfiguration

    Konfiguriere folgende Einstellungen:

    Ändere den Computernamen auf:

    <INT>-DC01

    Als Server sollte diese VM immer die gleiche IP-Adresse besitzen. Vergib deshalb eine statische IP entsprechend dem zu Beginn der Übung vorgegebenen Schema.

    Jetzt ist die VM bereit für die weiteren Aufgaben; mache jetzt einen Snapshot damit du diesen Zustand Notfalls wiederherstellen kannst.

    Teil 2 – Active Directory installieren

    Unter Windows Server werden verschiedene Dienste und deren Teile als "Rollen" und "Features" bezeichnet. Im Laufe dieser und der nächsten Übungen wirst du deinem Server einige davon hinzufügen. Die Schritte laufen immer ähnlich ab.

    Installiere die Rolle:

    Active Directory Domain Services

    über den Server Manager.

    Nach der Installation von Rollen gibt es häufig noch eine Post-deployment Configuration - in diesem Fall:

    Promote this server to a domain controller

    Erstelle eine neue Gesamtstruktur:

    <INT>.local

    Lege ein DSRM-Passwort fest.

    Keine DNS Delegation.

    Nach der Installation startet der Server automatisch neu.

    Teil 3 – Routing aktivieren

    Der DC muss Pakete zwischen internem und externem Netzwerk weiterleiten.

    Installiere die Rolle:

    Remote Access

    anschließend:

    Routing

    Danach im Assistenten von Routing and Remote Access (RRAS):

    Configure and Enable Routing and Remote Access

    Modus:

    Network Address Translation (NAT)

    wählen.

    Anschließend:

    • Bridged-Netzwerkkarte als Public Interface markieren
    • Internes Netz als Private Interface markieren

    <INT>-PC01 und <INT>-FS01 erhalten entweder per DHCP oder statisch die Gateway Adresse.

    Teil 4 – DNS konfigurieren

    Die DNS-Rolle wurde automatisch mitinstalliert, jetzt muss der DNS-Server noch konfiguriert werden. Zu den Einstellungen einer Rolle zu kommen geht auch bei allen zukünftig installierten Rollen ähnlich: wähle entweder in der linken Sidebar des Server Managers DNS, dann im Kontextmenü des Servers DC01 DNS Manager, oder im Menü Tools > DNS.

    Öffne den DNS Manager.

    Erstelle eine neue Reverse Lookup Zone für dein Netzwerk.

    192.168.<KN>.0/24

    Erstelle einen PTR-Eintrag für:

    <INT>-DC01

    Prüfe anschließend die Namensauflösung mit:

    nslookup <int>-dc01.nachname.local

    Damit Internetnamen aufgelöst werden können, konfiguriere DNS-Forwarder. Dieser Schritt wird auch in realen Unternehmensumgebungen verwendet.

    Verwende beispielsweise:

    8.8.8.8
1.1.1.1

    Teste anschließend:

    nslookup www.microsoft.com

    Teil 5 – AD strukturieren

    Öffne:

    Active Directory Users and Computers

    Organisationseinheiten (OUs) anlegen

    Erstelle folgende Struktur:

    TechSolutions
 ├─ Benutzer
 │   ├─ Allgemein
 │   ├─ IT
 │   ├─ Vertrieb
 │   └─ Verwaltung
 │
 ├─ Computer
 │
 └─ Server

    Diese Struktur orientiert sich an typischen Unternehmensumgebungen.

    Sicherheitsgruppen erstellen

    Lege folgende globale Sicherheitsgruppen an:

    GG_IT
GG_Vertrieb
GG_Verwaltung

    Benutzer anlegen

    Damit man sich später mit einem Client an der Domäne anmelden kann, braucht es einen Domänenbenutzer.

    Erstelle mindestens 2 Benutzer pro Organisationseinheit.

    Für alle Benutzer:

    Passwort: Password1!

    Nachdem der neue Benutzer angelegt wurde, kannst du mit Doppelklick auf dessen Namen die Details des Kontos ansehen. Hier können noch weitere Informationen eingetragen, der Benutzer zu Gruppen hinzugefügt werden und vieles mehr. Unter dem Reiter „Member of“ siehst du in welchen Gruppen der Benutzer Mitglied ist. Standardmäßig ist ein neuer Benutzer nur Mitglied der Gruppe Domain Users.

    Aktiviere:

    Benutzer muss Kennwort bei nächster Anmeldung ändern

    Ordne die Benutzer den passenden Gruppen zu.

    Teil 6 – DHCP installieren

    Unser Server soll in unserem Netzwerk auch als DHCP-Server fungieren. Dazu müssen wir zunächst den DHCP-Dienst von VMware Workstation beenden. Fahre dazu den Server herunter. Klicke dann in VMware Workstation auf den Reiter "Edit" und dann auf "Virtual Network Editor".

    Entferne das Häkchen bei Use local DHCP service to distribute IP addresses to VMs.

    Installiere die Rolle:

    DHCP Server

    auf <INT>-DC01.

    Autorisieren den DHCP-Server innerhalb der Domäne.

    Konfiguriere einen Scope:

    Name: LAN
Start-IP: 192.168.<KN>.100
End-IP:   192.168.<KN>.200

    Reserviere die Adressen der Server durch Ausschlussbereiche.

    Beispiel:

    192.168.<KN>.10
192.168.<KN>.20

    DNS-Server:

    192.168.<KN>.10

    Gateway:

    192.168.<KN>.1

    DNS-Suffix:

    <INT>.local

    Damit ist der Domaincontroller bereit! Mache am besten wieder einen Snapshot.

    Teil 7 – Fileserver bereitstellen

    Installiere einen zweiten Windows Server 2022.

    Name:

    <INT>-FS01

    Als Server sollte diese VM immer die gleiche IP-Adresse besitzen. Vergib deshalb eine statische IP entsprechend dem zu Beginn der Übung vorgegebenen Schema.

    Füge <INT>-FS01 zur Domäne hinzu.

    Melde dich mit einem Domänenadministrator an.

    Nach erfolgreichem Domänenbeitritt:

    • Neustarten
    • Computerkonto in die OU Server verschieben

    Erstelle folgende Verzeichnisse:

    <Laufwerk>:\Freigaben\Allgemein
<Laufwerk>:\Freigaben\IT
<Laufwerk>:\Freigaben\Vertrieb
<Laufwerk>:\Freigaben\Verwaltung

    Berechtigungen konfigurieren

    Für jede Abteilung richte die entsprechenden Berechtigungen auf dem freigegebenen Ordner ein. Beispielsweise darf die odass die Personalabteilung nicht auf den Finanzordner zugreifen.

    Ordner Berechtigte Gruppe
    Allgemein Domain Users
    IT GG_IT
    Vertrieb GG_Vertrieb
    Verwaltung GG_Verwaltung

    Administratoren erhalten Vollzugriff.

    Aktuell wurden nur Ordner und NTFS-Berechtigungen erzeugt. Zusätzlich müssen diese als Netzwerkfreigabe veröffentlicht werden.

    Freigaben konfigurieren

    Erstelle für die zuvor angelegten Verzeichnisse entsprechende SMB-Freigaben.

    Ordner Freigabename
    <Laufwerk>:\Freigaben\Allgemein Allgemein
    <Laufwerk>:\Freigaben\IT IT
    <Laufwerk>:\Freigaben\Vertrieb Vertrieb
    <Laufwerk>:\Freigaben\Verwaltung Verwaltung

    Funktionstest

    Melde dich mit Benutzern unterschiedlicher Abteilungen am Client an und überprüfe:

    • Zugriff auf die Freigabe Allgemein
    • Zugriff auf die eigene Abteilungsfreigabe
    • kein Zugriff auf Freigaben anderer Abteilungen

    Beispiel:

    Ein Benutzer der Gruppe GG_IT darf auf

    \\<INT>-FS01\IT

    zugreifen, jedoch nicht auf

    \\<INT>-FS01\Verwaltung

    Man kann den Fileserver auch um zusätzliche Verwaltungsfunktionen erweitern. Dies ist nicht Teil der Übung, kannst du aber selber ausprobieren.

    Installiere dafür die Rolle:

    File and Storage Services
 └ File and iSCSI Services
    └ File Server Resource Manager

    und schaue dir die folgenden Themen an:

    • File Server Resource Manager (FSRM)

    • Quotas

    • Access Based Enumeration (ABE)

    • Dateiserver-Verwaltung mit dem Server Manager

    Teil 8 – Client installieren

    Erstelle eine virtuelle Maschine:

    <INT>-PC01

    Verwende Windows 10 oder Windows 11.

    Lokaler Benutzer:

    win10admin oder win11admin

    Passwort:

    Password1!

    Nicht automatisch einloggen; wir wollen ja einen Domänenbenutzer konfigurieren!

    Bei der Installation wirst du nach einer Netzwerkverbindung gefragt. Diesen Schritt kannst du überspringen

    Mache nach erfolgreicher Installation einen Snapshot.

    Teil 9 – Client in die Domäne aufnehmen

    Achtung: Damit du den Client der Domäne hinzufügen kannst, muss der Server eingeschalten sein.

    Ändere den Computernamen auf:

    <INT>-PC01

    Um den Client in die Domäne aufzunehmen, öffne Systemsteuerung > System und Sicherheit > System (Windows + Pause führt z.B. direkt dort hin). Das führt entweder auf einen Teil der Systemsteuerung (klicke dort auf Einstellungen ändern) oder auf die Settings App, zu der man auch kommt wenn man im Startmenü View your PC name sucht (klicke dort auf Rename this PC (Advanced))

    Diese Aktion muss von einem Domänenadministrator bestätigt werden, in userem Fall sind die Credentials als Administrator/Password1!.Nach einem Neustart ist der Client Mitglied der Domäne.

    Starte den Client neu.

    Klicke beim Anmeldebildschirm unten auf Anderer Benutzer und melde dich mit deinem Domänenbenutzer an. Wichtig ist, dass unter dem Anmeldefenster steht, dass du dich an deiner Domäne anmeldest. Sollte dies nicht der Fall sein, kannst du dich an der Domäne anmelden, indem du [Domain]\[Benutzername] oder [Benutzername]@[Domain] als Benutzername eingibst. Der lokale Administrator-Account wird in dieser Schreibweise als PC01\win10admin geschrieben.

    Beim ersten Login muss das Passwort geändert werden.

    Verschiebe anschließend das Computerkonto nach:

    TechSolutions
 └─ Computer

    Teil 10 – Funktionstest

    Prüfe die gesamte Umgebung.

    Active Directory

    Anmeldung eines Domänenbenutzers möglich

    DNS

    nslookup <INT>-dc01.nachname.local
nslookup <INT>-fs01.nachname.local

    DHCP

    ipconfig /all

    Kontrolliere zusätzlich auf DC01:

    DHCP
 └ IPv4
   └ Address Leases

    Der Client PC01 muss sichtbar sein.

    Netzwerk

    ping <INT>-dc01
ping <INT>-fs01

    Fileserver

    Zugriff auf:

    \\<INT>-FS01\Allgemein

    Erstelle testweise eine Datei.

    Internet-DNS

    nslookup www.microsoft.com

    Aufgabe Erweiterte Kompetenz:

    In größeren IT-Umgebungen werden Server häufig nicht direkt per Remote Desktop verwaltet. Stattdessen kommen zentrale Administrationswerkzeuge zum Einsatz. Mit dem Windows Admin Center (WAC) stellt Microsoft eine browserbasierte Verwaltungsoberfläche bereit, über die Windows Server, Windows-Clients und weitere Systeme zentral administriert werden können. Das Windows Admin Center verwendet dabei eine Gateway-Komponente und kommuniziert mit den verwalteten Systemen über etablierte Verwaltungsprotokolle wie WinRM und PowerShell Remoting.

    Teil 11 – Windows Admin Center

    Du installierst und konfigurierst das Windows Admin Center innerhalb deiner bestehenden Domänenumgebung und verwendest es zur Verwaltung von DC01, FS01 und PC01.

    Lade das aktuelle Windows Admin Center von Microsoft herunter.

    https://aka.ms/WACDownload

    Alternativ kann der Download über das Microsoft Evaluation Center erfolgen.

    Das Windows Admin Center soll auf <INT>-FS01 installiert werden.

    Hinweis: In produktiven Umgebungen wird empfohlen, Windows Admin Center auf einem separaten Verwaltungsserver zu betreiben. Für unsere Laborumgebung verwenden wir FS01. Domain Controller sollten hierfür nicht verwendet werden.

    Melde dich auf FS01 als Domänenadministrator an.

    Starte anschließend die Installationsdatei. Für die Laborumgebung genügt die Standardkonfiguration.

    Lass ein selbstsigniertes Zertifikat erzeugen.

    In Produktionsumgebungen sollte ein Zertifikat einer vertrauenswürdigen Zertifizierungsstelle verwendet werden.

    Erlaube eingehende HTTPS-Verbindungen (Port: 443).

    Öffne auf PC01 einen Browser.

    Rufe folgende Adresse auf:

    https://<INT>-FS01

    oder

    https://<INT>-fs01.nachname.local

    Akzeptiere gegebenenfalls die Zertifikatswarnung.

    Melde dich mit einem Domänenadministratorkonto an.

    Füge folgende Systeme zur Verwaltung hinzu:

    <INT>-DC01
<INT>-FS01
