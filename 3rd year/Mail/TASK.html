    Lokaler Mailserver mit SMTP und IMAP

    Einführung

    E-Mails sind ein zentraler Bestandteil moderner IT-Infrastrukturen. Hinter dem einfachen Versand und Empfang von Nachrichten arbeiten mehrere Dienste und Protokolle zusammen, um eine zuverlässige Zustellung zu ermöglichen.

    In dieser Übung wird ein eigener Mailserver auf Basis von Postfix und Dovecot eingerichtet. Zunächst werden lokale Benutzerkonten angelegt und E-Mails innerhalb eines Systems ausgetauscht. Anschließend werden die zugrunde liegenden Protokolle SMTP (Versand) und IMAP (Abruf) analysiert und manuell getestet. Darüber hinaus werden gespeicherte Nachrichten, E-Mail-Header, Netzwerkverkehr und TLS-verschlüsselte Verbindungen untersucht.

    In der Erweiterung der Übung werden zwei unabhängige Mailserver unterschiedlicher DNS-Domänen miteinander verbunden. Dabei kommen eigene DNS-Server und MX-Records zum Einsatz, sodass die Mailserver die Gegenstelle selbstständig ermitteln und E-Mails domänenübergreifend zustellen können. Dadurch wird der grundlegende Ablauf des E-Mail-Verkehrs im Internet praxisnah nachgebildet.

    Ziele

    • die Aufgaben von SMTP und IMAP erklären
    • einen lokalen Mailserver mit Postfix und Dovecot konfigurieren
    • E-Mails zwischen lokalen Benutzern versenden
    • SMTP-Kommandos manuell testen
    • TLS-Verbindungen analysieren
    • Netzwerkverkehr mittels tcpdump untersuchen.

    Kompetenzzuordnung

    Übertragungsmedien und Netztopologien

    • ein SOHO-Netzwerk installieren
    • bei gegebenen Anforderungen an Netzwerke Lösungskonzepte zur Realisierung von Topologien erarbeiten

    Voraussetzungen

    • Abschluss der Übung DNS

    Detaillierte Aufgabenbeschreibung

    Ein lokaler Mailserver soll eingerichtet werden. Zwei Benutzer (alice und bob) kommunizieren ausschließlich innerhalb des Systems.

    Protokoll Port Aufgabe
    SMTP 25 Versand von E-Mails
    SMTP Submission 587 Versand authentifizierter E-Mails
    IMAP 143 Abruf und Verwaltung von E-Mails
    IMAPS 993 Verschlüsselter IMAP-Zugriff

    Teil 1 – Installation

    In diesem Abschnitt werden alle Komponenten installiert, die für einen Mailserver benötigt werden.

    Aktualisiere das System und installiere die benötigten Pakete.

    sudo apt update
sudo apt install -y postfix dovecot-core dovecot-imapd mailutils telnet tcpdump openssl

    Während der Installation von Postfix wähle:

    General mail configuration type:
→ Internet Site

    Anschließend:

    System Mail Name:
→ server.Schülername.lokal

    Beispieladressen im Labor:

    alice@Schülername.lokal
bob@Schülername.lokal

    Anpassung der Postfix-Konfiguration

    In /etc/postfix/main.cf:

    myhostname = mail.Schülername.lokal
mydomain = Schülername.lokal

myorigin = $mydomain
mydestination = $myhostname, localhost.$mydomain, localhost, $mydomain
inet_interfaces = all
inet_protocols = ipv4
home_mailbox = Maildir/

    Danach neu starten:

    sudo systemctl restart postfix1
sudo systemctl enable postfix

    Kontrolliere, ob der Dienst läuft:

    sudo systemctl status postfix

    Prüfe die Ports:

    ss -ltnp | grep :25

    Der Server sollte nun auf SMTP-Port 25 lauschen.

    Teil 2 – Benutzer anlegen

    Die lokalen Linux-Benutzer dienen als Mailkonten des Mailservers.

    Jeder Benutzer besitzt:

    • ein Home-Verzeichnis
    • ein Maildir-Verzeichnis
    • ein eigenes Postfach

    Lege zwei Benutzer an:

    sudo adduser alice
sudo adduser bob

    Überprüfen die Benutzer:

    getent passwd alice
getent passwd bob

    Optional: Falls nach der ersten Mailzustellung kein Maildir-Verzeichnis erzeugt wurde, lege die Verzeichnisstruktur manuell an.

    sudo -u alice mkdir -p ~/Maildir/{cur,new,tmp}
sudo -u bob mkdir -p ~/Maildir/{cur,new,tmp}
sudo chmod -R 700 /home/alice/Maildir
sudo chmod -R 700 /home/bob/Maildir

    Teil 3 – Dovecot konfigurieren

    Dovecot stellt die von Postfix gespeicherten E-Mails über IMAP bereit.

    Öffne die Datei:

    sudo nano /etc/dovecot/conf.d/10-mail.conf

    Suche nach mail_location und ändere auf:

    mail_location = maildir:~/Maildir

    Öffne anschließend:

    sudo nano /etc/dovecot/dovecot.conf

    Kontrolliere:

    protocols = imap

    Dovecot neu starten:

    sudo systemctl restart dovecot

    Status prüfen:

    sudo systemctl status dovecot

    Prüfe, ob Dovecot auf dem IMAP-Port 143 lauscht:

    ss -ltnp | grep 143

    Erwartete Ausgabe:

    LISTEN 0      100      0.0.0.0:143      0.0.0.0:*
LISTEN 0      100         [::]:143         [::]:*

    Teil 4 – Sende eine Testmail

    Postfix soll eine E-Mail vom Benutzer Alice an den Benutzer Bob zustellen.

    Wechsel zu Alice:

    su - alice

    Versende die Mail:

    echo "Hallo Bob!" | mail -s "Testmail" bob

    Die Nachricht wird über Postfix zugestellt.

    /home/bob/Maildir/new/<file>

    Überprüfen auch das Postfix-Log:

    sudo tail -20 /var/log/mail.log

    Suche nach:

    status=sent

    Teil 5 – Postfach überprüfen (Maildir ohne Dovecot)

    Neben dem Zugriff über IMAP können E-Mails auch direkt im Maildir-Verzeichnis des Benutzers eingesehen werden. Dadurch wird sichtbar, wie Postfix die Nachrichten lokal speichert.

    Die lokal gespeicherten Nachrichten sollen direkt untersucht werden.

    Wechsel zu Bob:

    su - bob

    Zeigen die eingegangenen Nachrichten an:

    mail

    Melde dich als Administrator oder Benutzer bob an und liste die neu eingegangenen Nachrichten auf:

    ls -l /home/bob/Maildir/new/

    Beispielausgabe:

    -rw------- 1 bob bob 512 Jun 10 14:32 1749561234.Vfd01I1234.mail

    Jede Datei entspricht einer einzelnen E-Mail.

    Zeigen Sie den Inhalt der gespeicherten E-Mail an:

    cat /home/bob/Maildir/new/*

    Beispielausgabe:

    From: alice@Schülername.lokal
To: bob@Schülername.lokal
Subject: Testmail
Hallo Bob

    Jede E-Mail besteht aus zwei Teilen:

    1. Header (Metadaten der Nachricht)
    2. Body (eigentlicher Nachrichtentext)

    Die Header enthalten wichtige Informationen über Absender, Empfänger, Zustellweg und Identifikation der Nachricht.

    Fassie die wichtigsten Headerfelder zusammen und erkläre deren Bedeutung.

    Teil 6 – SMTP manuell testen

    SMTP soll ohne Mailprogramm direkt über das Protokoll getestet werden.

    Öffnen eine Verbindung zum SMTP-Server:

    telnet localhost 25

    Gib die folgenden SMTP-Kommandos ein:

    EHLO client
MAIL FROM:<alice@Schülername.lokal>
RCPT TO:<bob@Schülername.lokal>
DATA
Hallo Bob!
Dies ist ein SMTP-Test.
.
QUIT

    Beobachte und interpretiere die Serverantworten.

    Typische Statuscodes:

    220 Service Ready
250 OK
354 Start Mail Input
221 Service Closing Transmission Channel

    Teil 7 - IMAP-Login testen

    Dovecot soll die gespeicherten Nachrichten über IMAP bereitstellen.

    Verbinde dich über Telnet mit dem IMAP-Dienst:

    telnet localhost 143

    Nach erfolgreicher Verbindung sollte eine Begrüßungsmeldung ähnlich der folgenden erscheinen:

    * OK Dovecot ready.

    Melden dich anschließend als Benutzer bob an:

    a login bob <passwort>

    Erwartete Antwort:

    a OK Logged in.

    Lass dir die vorhandenen Mailboxen anzeigen:

    a list "" *

    Beispielantwort:

    * LIST (\HasNoChildren) "." INBOX
a OK List completed.

    Wählen den Posteingang aus:

    a select INBOX

    Beispielausgabe:

    * FLAGS (\Answered \Flagged \Deleted \Seen \Draft)
* 4 EXISTS
* 0 RECENT
a OK [READ-WRITE] Select completed.

    Erste E-Mail anzeigen

    a fetch 1 body[]

    Beispielausgabe:

    * 1 FETCH (BODY[] {250}
Return-Path: <alice@Schülername.lokal>
Subject: Testmail
From: alice@Schülername.lokal
To: bob@Schülername.lokal
Hallo Bob!
Dies ist eine Testnachricht.
)
a OK Fetch completed.

    Melde dich wieder ab.

    a logout

    Erwartete Antwort:

    * BYE Logging out
a OK Logout completed.

    Teil 8 – Netzwerkverkehr mitschneiden

    Der Netzwerkverkehr eines Mailservers soll sichtbar gemacht werden.

    Starte einen Paketmitschnitt:

    sudo tcpdump -i lo port 25 -A

    Sende anschließend eine E-Mail.

    Beobachte und interpretiere:

    • SMTP-Handshake
    • EHLO
    • MAIL FROM
    • RCPT TO
    • DATA
    • QUIT

    Teil 9 – Analyse einer TLS-Verbindung

    Testen die verschlüsselte Verbindung zum Mailserver:

    openssl s_client -connect localhost:993

    Dokumentiere:

    • TLS-Version
    • Verwendete Cipher Suite
    • Zertifikatsinformationen
    • Ablaufdatum des Zertifikats

    Typische Fehlerquellen

    Die Firewall blockiert (Port 25)

    Auch wenn der Ping (ICMP) durchgeht, kann es sein, dass der Mail-Port (Port 25) blockiert wird.

    Prüfe, ob eine Firewall aktiv ist und den Port blockiert:

    sudo ufw allow 25/tcp
sudo ufw reload

    Teil 10 - E-Mail-Austausch zwischen zwei Mailservern mittels DNS und MX-Records vorbereiten

    Zwei bereits funktionierende Mailserver sollen miteinander kommunizieren. Jeder Schüler betreibt:

    • einen Mailserver (Postfix + Dovecot)
    • einen autoritativen DNS-Server für seine Domäne

    Die Mailserver sollen die Ziel-Mailserver über DNS-MX-Records finden.

    Ergänze die DNS-Zone von Schüler A und Schüler B jeweils mit:

    mail  IN A  192.168.KN.10
ns1   IN A  192.168.KN.10
@    IN MX 10 mail.Schuelername.lokal.

    Zusätzlich benötigen wir einen autoritativen Nameserver für die Zone lokal.. Aus Gründen der Ausfallsicherheit kann dies auf beiden Server_KN ergänzt werden. Normalerweise als Primary und Secondary, aus Einfachheit aber hier doppelt konfiguriert.

                         lokal.
                       |
         +-------------+-------------+
         |                           |
         v                           v
ns1.SchülernameA.lokal   ns1.SchülernameB.lokal
   192.168.KN.10              192.168.KN.20

    Darin stehen lediglich die Delegationen:

    $ORIGIN lokal.
team1  NS ns1.SchülernameA.lokal.
team2  NS ns1.SchülernameA.lokal.
ns1.SchülernameA.lokal. A 192.168.KN.10
ns1.SchülernameB.lokal. A 192.168.KN.20

    Validierung auf beiden Mailservern:

    dig mail.SchülernameA.lokal
dig mail.SchülernameA.lokal
dig MX SchülernameA.lokal
dig MX SchülernameB.lokal

    Wir benötigen noch eine statische Route auf beiden Server_KN damit sich die beiden Schülernetze über das gemeinsame Schulnetz erreichen können.

    sudo ip route add 192.168.KN.0/24 via <gegenüberliegende Server_KN_Outside_IP>

    Anschließend kontrollieren:

    ip route

    Prüfen in beiden Richtungen, ob das Zielnetz erreichbar ist:

    ping 192.168.KN.10
tracepath 192.168.KN.10

    Um die Route persistent zu speichern muss die Netplan-Konfiguration bearbeitet werden.

    sudo nano /etc/netplan/00-installer-config.yaml

    Beispiel:

    network:
  version: 2
  ethernets:
    eth1:
      addresses:
        - ...
      routes:
        - to: 192.168.<gegenüberliegende KN>.0/24
          via: <gegenüberliegende Server_KN_Outside_IP>

    Überprüfen, ob der ermittelte Mailserver erreichbar ist.

    Von Schüler A Server:

    telnet mail.SchülernameB.lokal 25

    Von Schüler B Server:

    telnet mail.SchülernameA.lokal 25

    Erwartete Antwort:

    220 mail.SchülernameA.lokal ESMTP Postfix

    Optional:

    Um sich von veränderlichen Adressen aufgrund des Schulnetzwerksetups unabhängig zu machen kann eine zusätzliche IP Adresse vergeben werden. Hier muss dann auch noch NAT angepasst werden.

    eth1
├── DHCP-Adresse:   10.0.X.Y/24 (vom Schul DHCP Server)
└── Zusätzliche IP: 192.168.100+<Zug>.<KN>/24

    <Zug> = Ascii Code von A, B, C, D

    sudo nano /etc/netplan/00-installer-config.yaml

    Beispiel:

    network:
  version: 2
  ethernets:
    eth1:
      dhcp4: true
      addresses:
        - 192.168.100+<Zug>.<KN>/24

    Anwenden:

    sudo netplan try
sudo netplan apply

    Kontrolle:

    ip addr show eth1

    Nicht vergessen die statische Route anzupassen!

    Teil 11 - E-Mail-Austausch zwischen zwei Mailservern mittels DNS und MX-Records vorbereiten

    Postfix soll den Ziel-Mailserver automatisch über DNS ermitteln.

    Alice → Bob

    Auf Schüler A Server:

    su - alice

    echo "Hallo Bob!" | \
mail -s "Mail zwischen Domänen" \
bob@SchülernameB.lokal

    Bob → Alice

    Auf Schüler B Server:

    su - bob

    echo "Hallo Alice!" | \
mail -s "Antwort" \
alice@SchülernameA.lokal

    Kontrolle auf dem Zielsystem:

    mail
ls ~/Maildir/new

    Teil 12 – Mail Header analysieren

    Vollziehe den Weg einer E-Mail zwischen zwei Mailservern nach.

    cat ~/Maildir/new/*

    Untersuche:

    • Welche Mailserver erscheinen in den Received-Zeilen?
    • Welche Informationen liefert die Message-ID?
    • Warum fügt jeder Mailserver eigene Header hinzu?

    Teil 13 – SMTP analysieren

    Mache die Kommunikation zwischen zwei Mailservern sichtbar.

    Empfänger-Server

    sudo tcpdump -i any port 25 -A

    Sender-Server

    Erneut eine E-Mail versenden.

    Beobachten Sie:

    EHLO
MAIL FROM
RCPT TO
DATA
QUIT

    Teil 14 – Reflexion

    • Warum benötigt ein Mailserver einen DNS-Server?
    • Welche Aufgabe erfüllen MX-Records?
    • Wie findet ein Mailserver den Zielserver für eine beliebige E-Mail-Adresse?
    • Warum funktioniert der Versand zwischen zwei Domänen ohne manuelle Transport-Konfiguration?
    • Welche Gemeinsamkeiten bestehen zwischen dieser Übung und dem Versand einer E-Mail an Gmail oder Microsoft 365?
    • Welche zusätzlichen Sicherheitsmechanismen werden im Internet eingesetzt (z. B. SPF, DKIM, DMARC)?
    • Welche Probleme würden auftreten, wenn kein MX-Record für eine Domäne konfiguriert wäre?

    Fragestellungen

    • Warum benötigt ein E-Mail-System sowohl SMTP als auch IMAP?
    • Welche Aufgabe hat SMTP beim Versand einer E-Mail?
    • Welche Aufgabe hat IMAP beim Abruf einer E-Mail?
    • Welche Informationen enthalten die Header-Felder einer Mail?
    • Warum ist die Message-ID für einen Mailserver wichtig?
    • Welche SMTP-Kommandos wurden beim manuellen Test verwendet? Ordne den SMTP-Kommandos ihre jeweilige Funktion zu.
    • Welche IMAP-Kommandos wurden in der Übung verwendet? Ordne den IMAP-Kommandos ihre jeweilige Funktion zu.
