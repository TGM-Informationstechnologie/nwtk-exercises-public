    DHCP-Server unter Linux einrichten

    Einführung

    In dieser Übung lernst du die grundlegende Funktionsweise des Dynamic Host Configuration Protocol (DHCP) kennen und setzt einen eigenen DHCP-Server in einer virtuellen Umgebung um. DHCP ist ein zentraler Netzwerkdienst, der Endgeräten automatisch IP-Adressen sowie weitere Netzwerkinformationen wie Standard-Gateway und DNS-Server zuweist. Dadurch wird die manuelle Konfiguration von Netzwerkgeräten vereinfacht und die Verwaltung größerer Netzwerke erleichtert.

    Zur Umsetzung wird eine isolierte Laborumgebung mit VMware Workstation verwendet. Dabei erstellst du virtuelle Maschinen, arbeitest mit Snapshots und Klonen, sowie der Konfiguration von virtuellen Netzwerken.

    Du definierst DHCP-Adressbereiche (Pools), analysierst die Vergabe von IP-Adressen anhand von DHCP-Leases und überprüfst die korrekte Funktion des Dienstes mithilfe eines Clients.

    Ein weiterer Schwerpunkt liegt auf der Konfiguration von statischen DHCP-Reservierungen, bei denen bestimmte Geräte anhand ihrer MAC-Adresse immer dieselbe IP-Adresse erhalten. Dadurch werden praktische Anwendungsfälle aus realen Netzwerken nachgebildet, beispielsweise die feste Adressierung von Druckern, Servern oder anderen Netzwerkdiensten.

    Im erweiterten Kompetenzbereich beschäftigst du dich mit professionellen Anforderungen an hochverfügbare Netzwerke. Dabei werden verschiedene DHCP-Redundanzmechanismen wie Split Scope, Failover und High-Availability-Lösungen untersucht und bewertet. Zusätzlich analysierst du die moderne DHCP-Lösung Kea DHCP, die den mittlerweile abgekündigten ISC DHCP Server als Nachfolgeprodukt ersetzt.

    Ziele

    • die Funktionsweise des Dynamic Host Configuration Protocol (DHCP) erklären.
    • virtuelle Maschinen in VMware erstellen, klonen und konfigurieren.
    • den DHCP-Dienst isc-dhcp-server unter Ubuntu installieren und konfigurieren.
    • DHCP-Adressbereiche (Pools) definieren und verwalten.
    • DHCP-Leases analysieren und Fehler in der Konfiguration erkennen.
    • statische DHCP-Reservierungen (Fixed Address) anhand von MAC-Adressen konfigurieren.

    Kompetenzzuordnung

    Übertragungsmedien und Netztopologien

    • ein SOHO-Netzwerk installieren
    • bei gegebenen Anforderungen an Netzwerke Lösungskonzepte zur Realisierung von Topologien
      erarbeiten

    Voraussetzungen

    • Saubere Basisinstallation von Ubuntu innerhalb von VMware Workstation (keine GUI notwendig)
    • Gutes Verständnis zu virtuellen Netzwerken innerhalb von VMware Workstation

    Detaillierte Aufgabenbeschreibung

    Wichtiger Hinweise:

    • Wir installieren die Software zuerst im NAT-Modus, damit Internet vorhanden ist. Danach stellen wir auf VMnet1 um (Isolierung).
    • An Stellen markiert mit KN muss die eigene Katalognummer eingesetzt werden.
    • Es ist besonders auf die Konfiguration des virtullen Netzwerkes zu achten, da es bei einer fehlerhaften Konfiguration zur Störung des Schulnetzwerkes kommen kann.

    Aufgabe Grundkompetenz:

    Teil 1 - Virtuelle Maschinen vorbereiten (Snapshot & Klonen)

    Name IP Adresse Beschreibung Betriebssystem
    Client_KN Dynamisch Client Ubuntu oder Windows
    Server_KN 192.168.KN.10 (Host-Only) DHCP Server Ubuntu
    1. Snapshot: Rechtsklick auf die ausgeschaltete Master-VM -> Snapshot -> Take Snapshot.... Name: Basis_sauber.
    2. Klonen: Rechtsklick auf Master-VM -> Manage -> Clone....
    3. Quelle: An existing snapshot (Basis_sauber).
    4. Typ: Create a full clone.
    5. Name: Client_KN.
    6. Name: Server_KN.
    7. Netzwerk: Beide VMs müssen vorerst auf NAT bleiben.

    Teil 2 - Software-Installation (VMNet8 = NAT Modus)

    Starte Server_KN. und installiere die notwendige Software:

    sudo apt update && sudo apt install isc-dhcp-server -y

    VM danach ausschalten: sudo shutdown now.

    Teil 3 - Netzwerk-Isolierung (VMnet1 = Host-Only)

    1. VMware Editor: Edit -> Virtual Network Editor.
    2. DHCP deaktivieren: Bei VMnet1 den Haken entfernen bei: "Use local DHCP service...".
    3. VM-Settings: Bei beiden VMs den Netzwerkadapter auf Custom: VMnet1 (Host-only) umstellen.

    Teil 4 - Server Netzwerkkonfiguration vornehmen

    Starte Server_KN.

    Prüfe die Interfacenamen:

    ip a

    (Standard ist meist ens160. Falls Ihr Name anders ist, nutzen Sie diesen statt ens160!)

    Nutze netplan um eine statische IP Adresse zu vergeben.

    Datei öffnen: sudo nano /etc/netplan/00-installer-config.yaml

    Wichtig: Achte auf die Leerzeichen! Keine Tabs verwenden!

    network:
  version: 2
  renderer: networkd
  ethernets:
    ens160:
      dhcp4: no
      addresses:
        - 192.168.KN.10/24

    Aktiviere die aktualisierte Konfiguration mit:

    sudo netplan apply

    Teil 5 - DHCP Pool konigurieren

    Die Datei dhcpd.conf ermöglicht dem Linux-Systemadministrator die Anpassung des DHCP-Servers. Sie enthält in der Regel globale Einstellungen (Optionen, die für das gesamte Netzwerk gelten) und Subnetz-Deklarationen (Optionen, die nur für das jeweilige Subnetz gelten). Nach jeder Änderung an dieser Datei muss der DHCP-Dienst neu geladen werden, damit die neuen Einstellungen wirksam werden.

    Wichtig: Fehler in dieser Datei (z. B. Tippfehler oder fehlende Semikolons) können dazu führen, dass der DHCP-Server nicht neu startet!

    Öffne: sudo nano /etc/dhcp/dhcpd.conf Ganz unten einfügen:

    subnet 192.168.KN.0 netmask 255.255.255.0 {
  range 192.168.KN.100 192.168.KN.200;
  option routers 192.168.KN.10;
  option domain-name-servers 8.8.8.8;
  default-lease-time 600;
  max-lease-time 7200;
}

    Öffne: sudo nano /etc/default/isc-dhcp-server Zeile anpassen:

    INTERFACESv4="ens160"

    Dienst starten:

    sudo systemctl restart isc-dhcp-server
sudo systemctl status isc-dhcp-server

    Teil 6 - Funktionstest am Client

    Starte Client_KN.

    1. Lease erneuern:
    sudo dhclient -r
sudo dhclient -v

    1. Prüfen: ip a (IP Bereich .100 - .200 erwartet).

    2. Verbindungstest: ping 192.168.KN.10.

    Auf dem Server:

    cat /var/lib/dhcp/dhcpd.leases

    oder

    sudo tail -f /var/log/syslog

    Es sollte ersichtlich sein, dass die reservierte Adresse vergeben wurde.

    Teil 7 - Statische Lease

    Geräte in einem DHCP-Netzwerk werden häufig mit unterschiedlichen, zugewiesenen IP-Adressen konfiguriert, insbesondere Mobilgeräte. Manchmal ist es jedoch sinnvoller, einem Host eine feste Adresse zuzuweisen, beispielsweise für DNS-Einträge.

    DHCP vergibt zwar IP-Adressen dynamisch, kann aber auch eine IP-Adresse für einen bestimmten Computer reservieren. In diesem Fall hat der Client-Computer quasi eine statische IP-Adresse, obwohl er sie per DHCP bezieht. Unter Linux spricht man von der "Fixed Address". Microsoft nennt es "Reservation".

    Ziel: Ein bestimmter Client erhält bei jeder DHCP-Anfrage dieselbe IP-Adresse.

    MAC-Adresse des Clients ermitteln:

    ip link

    Beispielausgabe:

    link/ether 00:0c:29:12:34:56

    Unterhalb der Subnetzdefinition ergänzen:

    host client_kn {
  hardware ethernet 00:0c:29:12:34:56;
  fixed-address 192.168.KN.100;
}

    DHCP-Dienst neu starten, Lease erneuern und IP-Adresse prüfen.

    Teil 7 - DHCP-Redundanzmechanismen

    In produktiven Netzwerken darf der Ausfall eines DHCP-Servers nicht dazu führen, dass neue Geräte keine IP-Adresse mehr erhalten.

    Typische Redundanzmechanismen sind:

    • DHCP Failover
    • Split Scope
    • Mehrere DHCP-Server mit getrennten Pools
    • High Availability Cluster

    Erkläre jeden dieser Ansätze in eigenen Worten.

    Teil 8 - DHCP Failover mit ISC DHCP Server

    ISC DHCP unterstützt einen integrierten Failover-Mechanismus, bei dem zwei DHCP-Server ihre Lease-Datenbank synchronisieren. Fällt ein Server aus, kann der andere die Adressvergabe übernehmen.

    Bei ISC-Failover verwenden beide Server denselben Adresspool und synchronisieren die vergebenen Leases über das Failover-Protokoll.

    1. Konfiguriere DHCP-Failover zwischen zwei Ubuntu-Servern.

    2. Dokumentiere die Konfigurationsdateien.

    3. Weise nach, dass Lease-Daten synchronisiert werden.

    4. Führe einen Ausfalltest durch.

    5. Dokumentiere die beobachteten Failover-Status.

    6. Erkläre den Unterschied zwischen: Split Scope und DHCP Failover

    7. Warum gilt DHCP Failover als professionelle Lösung gegenüber Split Scope?

    Teil 9 - Migration von ISC DHCP zu Kea DHCP

    Der in dieser Übung verwendete ISC DHCP Server (isc-dhcp-server) wurde vom Hersteller ISC als End-of-Life (EOL) erklärt und wird nicht mehr aktiv weiterentwickelt. Für neue Installationen empfiehlt ISC die Verwendung des modernen Nachfolgers Kea DHCP.

    Kea bietet unter anderem:

    • moderne Softwarearchitektur
    • bessere Erweiterbarkeit
    • REST-API für Verwaltung und Automatisierung
    • Datenbankunterstützung
    • High-Availability-Funktionalitäten
    • aktive Weiterentwicklung und Fehlerbehebungen

    Recherchiere und beantworte folgende Fragen:

    1. Warum wurde die Entwicklung von ISC DHCP eingestellt?
    2. Welche Vorteile bietet Kea DHCP gegenüber ISC DHCP?
    3. Welche Herausforderungen können bei einer Migration von ISC DHCP zu Kea auftreten?
    4. Welche Konfigurationsformate verwenden ISC DHCP und Kea?
    5. Warum empfiehlt ISC neuen Installationen die Verwendung von Kea DHCP?

    Installiere Kea DHCP auf einer Test-VM und vergleiche dessen Konfiguration mit der zuvor erstellten ISC-DHCP-Konfiguration.

    • Installationsschritte
