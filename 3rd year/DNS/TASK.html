    DNS mit BIND9 – Namensauflösung im Netzwerk

    Einführung

    In dieser Übung lernst du, wie du im Netzwerk eigene Namen (z. B. server.Schuelername.lokal) statt komplizierter IP-Adressen verwendet. Dazu wird euer Linux-Server als DNS-Server (Domain Name System) konfiguriert. Der DNS-Server fungiert als „Telefonbuch“ des Netzwerks und übersetzt Namen in IP-Adressen.

    Zusätzlich werden folgende DNS-Konzepte behandelt:

    • Forward Lookup
    • Reverse Lookup
    • Rekursive Namensauflösung
    • DNS-Weiterleitung (Forwarding)
    • Secondary DNS (Slave Server)

    Die Umsetzung erfolgt mit BIND9 unter Linux.

    Ziele

    • DNS-Server mit BIND9 installieren und konfigurieren
    • Forward-Lookups erstellen und testen
    • Reverse-Lookups konfigurieren
    • Rekursive DNS-Auflösung verstehen
    • DNS-Forwarding einrichten
    • DNS-Dienst in ein bestehendes DHCP-Netz integrieren
    • DNS-Fehler mit geeigneten Werkzeugen analysieren

    Kompetenzzuordnung

    Übertragungsmedien und Netztopologien

    • ein SOHO-Netzwerk installieren
    • bei gegebenen Anforderungen an Netzwerke Lösungskonzepte zur Realisierung von Topologien erarbeiten

    Voraussetzungen

    • Abschluss der Übung NAT und PAT

    Detaillierte Aufgabenbeschreibung

    Installation und Konfiguration eines DNS-Servers mit BIND9.

    Anmerkungen:

    • Schülername durch euren Nachnamen ersetzen.
    • KN durch eure zugewiesene Nummer ersetzen.
    • Punkte am Ende von FQDNs sind erforderlich.

    Teil 1 – bind installieren

    Installation durchführen:

    sudo apt update
sudo apt install bind9 bind9utils bind9-dnsutils -y

    Teil 2 – DNS-Zone anlegen

    Dem DNS-Server muss mitgeteilt werden, für welche Domäne (Zone) er verantwortlich ist und wo die dazugehörigen DNS-Einträge gespeichert sind.

    sudo nano /etc/bind/named.conf.local

    Folgende Zone ergänzen:

    zone "Schülername.lokal" {
    type master;
    file "/etc/bind/db.schueler";
};

    Teil 3 – Forward Lookup konfigurieren

    Jetzt wird die eigentliche DNS-Zonendatei erstellt. In dieser Datei werden die Hostnamen und die dazugehörigen IP-Adressen gespeichert. Dadurch kann der DNS-Server später Anfragen nach Namen wie server.Schülername.lokal oder client.Schülername.lokal beantworten.

    sudo nano /etc/bind/db.schueler

    Inhalt:

    $TTL    604800
@       IN      SOA     Schülername.lokal. root.Schülername.lokal. (
                             2
                        604800
                         86400
                       2419200
                        604800 )

@       IN      NS      server.Schülername.lokal.
server  IN      A       192.168.KN.10
client  IN      A       192.168.KN.100

    DNS-Dienst neu starten und Status prüfen:

    sudo systemctl restart bind9
sudo systemctl status bind9

    Teste am Server:

    nslookup server.Schülername.lokal

    Teil 4 – Reverse Lookup konfigurieren

    In diesem Schritt wird ein Reverse Lookup eingerichtet. Während beim Forward Lookup ein Hostname in eine IP-Adresse übersetzt wird, funktioniert der Reverse Lookup genau umgekehrt:

    sudo nano /etc/bind/named.conf.local

    Ergänze:

    zone "KN.168.192.in-addr.arpa" {
    type master;
    file "/etc/bind/db.reverse";
};

    Reverse-Datei erstellen:

    sudo nano /etc/bind/db.reverse

    Inhalt:

    $TTL    604800
@       IN      SOA     Schülername.lokal. root.Schülername.lokal. (
                             1
                        604800
                         86400
                       2419200
                        604800 )
@       IN      NS      server.Schülername.lokal.
10      IN      PTR     server.Schülername.lokal.
100     IN      PTR     client.Schülername.lokal.

    Starte den Dienst neu.

    Teste am Server:

    dig -x 192.168.KN.10

    Teil 5 – DHCP anpassen

    Bisher wurde der DNS-Server so konfiguriert, dass er Namen wie server.Schülername.lokal auflösen kann. Damit die Clients diesen DNS-Server jedoch automatisch verwenden, muss die DHCP-Konfiguration angepasst werden.

    sudo nano /etc/dhcp/dhcpd.conf

    Subnet anpassen:

    subnet 192.168.KN.0 netmask 255.255.255.0 {
  range 192.168.KN.100 192.168.KN.200;
  option routers 192.168.KN.10;
  option domain-name-servers 192.168.KN.10;
  option domain-name "Schülername.lokal";
  default-lease-time 600;
  max-lease-time 7200;
}

    DHCP neu starten:

    sudo systemctl restart isc-dhcp-server

    Teil 6 – Teste am Client

    Nachdem DNS und DHCP konfiguriert wurden, soll überprüft werden, ob die Konfiguration vom Client korrekt übernommen wurde und die Namensauflösung funktioniert.

    Neue DHCP-Informationen beziehen:

    sudo dhclient -v -r
sudo dhclient -v

    DNS-Konfiguration prüfen:

    cat /etc/resolv.conf

    Namensauflösung testen:

    nslookup server.Schülername.lokal
dig server.Schülername.lokal
nslookup 192.168.KN.10
dig -x 192.168.KN.10

    Püfe die Namensauflösung direkt über deinen DNS-Server:

    nslookup server.Schülername.lokal 192.168.KN.10
dig @192.168.KN.10 server.Schülername.lokal

    Ping-Test:

    ping server.Schülername.lokal

    Teil 7 – DNS Aliasnamen

    In dieser Abschnitt erweiterst du deine DNS-Zone um Aliasnamen (CNAME-Records). Dadurch kann ein Host unter mehreren Namen erreichbar sein, ohne dass für jeden Namen eine eigene IP-Adresse eingetragen werden muss.

    1. Recherchiere die Funktion eines CNAME-Records.
    2. Erstelle für deinen Server mindestens zwei Aliase, z. B. dhcp, dns, ...
    3. Überprüfe die Auflösung der Aliasnamen.
    4. Vergleich die Ergebnisse mit einem normalen A-Record.

    Teil 8 – Rekursive Auflösung untersuchen

    DNS-Server können Anfragen entweder selbst vollständig auflösen (rekursiv) oder schrittweise an andere DNS-Server weitergeben (iterativ).

    Führt folgende DNS-Anfragen aus:

    nslookup google.com
dig google.com

    Untersucht anschließend den Weg der DNS-Auflösung:

    dig google.com +trace

    Falls +trace in deiner Laborumgebung nicht funktioniert, dokumentiere die Fehlermeldung und recherchiere die Ursache.

    Untersucht die Ausgabe und beantwortet folgende Fragen:

    • Welcher DNS-Server beantwortet die Anfrage bei nslookup?
    • Welche IP-Adresse wird für google.com zurückgegeben?
    • Welche zusätzlichen Informationen liefert dig?
    • Welche Server werden bei einer Auflösung mit +trace kontaktiert?
    • Welche Aufgabe haben:
      • Root-DNS-Server?
      • Top-Level-Domain-Server (z. B. .com)?
      • Autoritative DNS-Server?

    Teil 9 – DNS-Weiterleitung (Forwarding)

    Ein lokaler DNS-Server kennt in der Regel nur die eigenen DNS-Zonen. Für Anfragen zu externen Domains (z. B. microsoft.com) kann er die Namensauflösung an andere DNS-Server weiterleiten. Dieses Verfahren wird als DNS-Forwarding bezeichnet.

    sudo nano /etc/bind/named.conf.options

    Forwarder konfigurieren:

    options {
    directory "/var/cache/bind";
    recursion yes;
    forwarders {
        8.8.8.8;
        1.1.1.1;
    };
};

    Dienst neu starten und testen:

    sudo systemctl restart bind9
dig microsoft.com

    Teil 10 - Secondary DNS konfigurieren

    Zur Erhöhung der Ausfallsicherheit soll ein zweiter DNS-Server eingerichtet werden.

    Der zweite DNS-Server soll automatisch eine Kopie der DNS-Zone des Primary DNS erhalten und Anfragen beantworten können, falls der Primary DNS nicht verfügbar ist.

    1. Installiere auf einem zweiten Linux-Server den DNS-Dienst BIND9. Nutze Failover_KN dafür.
    2. Recherchiere den Unterschied zwischen Primary DNS (Master) und Secondary DNS (Slave)
    3. Pass die Konfiguration des Primary DNS so an, dass ein zweiter DNS-Server die Zonendaten beziehen darf.
    4. Konfiguriere den zweiten DNS-Server als Secondary DNS für deine Domäne Schülername.lokal.
    5. Starte beide DNS-Dienste neu und überprüfe, ob die Zonendaten erfolgreich übertragen wurden.
    6. Testet die Namensauflösung über den Secondary DNS.
    7. Simuliere einen Ausfall des Primary DNS und untersuche, ob die Namensauflösung weiterhin funktioniert.

    Teil 11 - Eigene Subdomain verwalten

    Das Unternehmen wächst und möchte die Abteilung „IT" in einer eigenen DNS-Zone verwalten.

    1. Legt eine zusätzliche DNS-Zone für die Subdomain it.Schülername.lokal an.
    2. Erstellt mindestens drei Hosts innerhalb dieser Subdomain.
    3. Sorgt dafür, dass diese Hosts per DNS aufgelöst werden können.
    4. Testet die Namensauflösung.
    5. Dokumentiert die notwendigen Änderungen.
