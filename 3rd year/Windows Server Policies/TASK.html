    Windows Enterprise Gruppenrichtlinien (GPO)

    Einführung

    In der vorhergehenden Übung wurde eine Windows-Domänenumgebung mit Domain Controller, DNS, DHCP, Fileserver und Domänenclients aufgebaut. In dieser Übung wird die zentrale Verwaltung der Clients durch Group Policy Objects (GPOs) erweitert.

    Gruppenrichtlinien ermöglichen Administratoren, Einstellungen zentral für Benutzer und Computer festzulegen. Dadurch können Unternehmensrichtlinien automatisch umgesetzt, Arbeitsplätze standardisiert und die Administration erheblich vereinfacht werden. Im Homelab-Szenario von Jared Leyva werden GPOs verwendet, um Benutzerumgebungen zentral zu konfigurieren und Unternehmensstandards durchzusetzen.

    Ziele

    • den Aufbau von Gruppenrichtlinien verstehen
    • GPOs erstellen und verwalten
    • GPOs auf Organisationseinheiten anwenden
    • Benutzer- und Computerrichtlinien unterscheiden
    • Desktop-Einstellungen zentral konfigurieren
    • Sicherheits- und Nutzungseinschränkungen umsetzen
    • die Vererbung und Anwendung von Gruppenrichtlinien überprüfen

    Kompetenzzuordnung

    Übertragungsmedien und Netztopologien

    • bei gegebenen Anforderungen an Netzwerke Lösungskonzepte zur Realisierung von Topologien erarbeiten
    • eine Kaufentscheidung für aktive Netzwerkkomponenten treffen

    Switching und Routing

    • Switching- und Routingkonzepte in SOHO-Netzwerken umsetzen
    • ein SOHO-Netzwerk installieren

    Voraussetzungen

    Die Übung "Windows Enterprise Umgebung" muss vollständig abgeschlossen sein.

    • Domain Controller <INT>-DC01
    • DNS funktionsfähig
    • DHCP funktionsfähig
    • Fileserver <INT>-FS01
    • <INT>-PC01 als Domänenclient
    • Benutzer und Gruppen vorhanden
    • OU-Struktur vorhanden
    TechSolutions
 ├─ Benutzer
 │   ├─ Allgemein
 │   ├─ IT
 │   ├─ Vertrieb
 │   └─ Verwaltung
 │
 ├─ Computer
 └─ Server

    Detaillierte Aufgabenbeschreibung

    Die TechSolutions GmbH möchte die Verwaltung ihrer Arbeitsplätze vereinheitlichen. Benutzer sollen unabhängig vom verwendeten Computer dieselben Unternehmensrichtlinien erhalten. Zusätzlich sollen bestimmte Einstellungen gegen Änderungen durch Benutzer geschützt werden.

    Die zentrale Verwaltung soll ausschließlich über Active Directory und Gruppenrichtlinien erfolgen. Ziel ist es, administrative Tätigkeiten zu vereinfachen und Unternehmensstandards automatisch durchzusetzen.

    Aufgabe Grundkompetenz:

    Teil 1 – Gruppenrichtlinienverwaltung öffnen

    Gruppenrichtlinienobjekte oder Group Policy Objects (GPOs) setzen für eine Gruppe eine oder mehrere Richtlinien, legen also bestimmte Einstellungen für ausgewählte Benutzer und/oder Computer fest - optional so, dass diese Einstellungen nicht geändert werden können.

    Melde dich auf <INT>-DC01 als Domänenadministrator an.

    Öffne:

    Tools
→ Group Policy Management

    Verschaffe dir einen Überblick über:

    Forest
Domain
Group Policy Objects
Group Policy Inheritance

    Teil 2 – Hintergrundbild zentral festlegen

    Als Beispiel werden wir für alle Benutzer einen Desktophintergrund festlegen; das Hintergrundbild wird im Allgemein Share hinterlegt. Lade dir dazu ein Wallpaper deiner Wahl aus dem Internet herunter. Speichere dieses Bild unter <Laufwerk>:\Freigaben\Allgemein.

    Bild vorbereiten

    Speichere ein Hintergrundbild deiner Wahl in der bestehenden Freigabe:

    \\<INT>-FS01\Allgemein

    Dokumentiere den verwendeten UNC-Pfad.

    GPO erstellen

    Erstelle ein neues Gruppenrichtlinienobjekt.

    Wähle im Server Manager Tools > Group Policy Management, dann Forest: [nachname].at > Domains > <INT>.at und dann im Kontextmenü Create a GPO in this domain, and link it here....

    Nenne die GPO:

    Desktop_Wallpaper

    Desktop-Hintergrund konfigurieren

    Wähle im Kontextmenü des neuen GPO "Edit...".

    Navigiere zu:

    User Configuration
 └ Policies
    └ Administrative Templates
       └ Desktop
          └ Desktop

    Wähle dann auf der rechten Seite "Desktop Wallpaper" mit der rechten Maustaste aus und klicke auf "Edit".

    Einstellungen:

    Enabled

    Wähle im neuen Fenster Enabled und wähle bei Wallpaper Name das zuvor heruntergeladene Bild aus.

    Der Pfad sollte wie folgt aussehen:

    \\<INT>-DC01.<INT>.lokal\Allgemein\[dein_wallpaper]

    Ein Pfad beginnend mit C:\ würde am Client nicht gefunden werden, deswegen muss ein UNC-Pfad benutzt werden!

    Wähle auch den Wallpaper Style passend zu deinem Bild.

    Nachdem die Einstellungen konfiguriert wurden, sollte man bei dieser Option im Group Policy Management Editor sehen können, dass diese nun aktiviert ist.

    Änderung verhindern

    Konfiguriere zusätzlich:

    User Configuration
 └ Policies
    └ Administrative Templates
       └ Control Panel
          └ Personalization

    Richtlinie:

    Prevent changing desktop background

    Status:

    Enabled

    Dadurch kann der Benutzer den Hintergrund nicht mehr selbst ändern.

    Du kannst nun den Group Policy Management Editor schließen. Wenn du nun das angelegte GPO auswählst, kannst du auf der rechten Seite den Reiter "Settings" auswählen. Hier siehst du alle Einstellungen, die in diesem GPO konfiguriert wurden.

    User Configuration
 └ Policies
    └ Administrative Templates
       └ Control Panel

    Konfiguriere:

    Prohibit access to Control Panel and PC Settings

    Status:

    Enabled

    Teste die Wirkung am Client.

    Teil 4 – Eingabeaufforderung sperren

    Erstelle ein GPO:

    CMD_Block

    Navigiere zu:

    User Configuration
 └ Policies
    └ Administrative Templates
       └ System

    Konfiguriere:

    Prevent access to the command prompt

    Status:

    Enabled

    Teste die Anmeldung mit einem normalen Benutzer.

    Teil 5 – USB-Speichergeräte blockieren

    Die Geschäftsführung möchte verhindern, dass Daten über USB-Sticks kopiert werden.

    Erstelle ein GPO:

    USB_Block

    Konfiguriere:

    Computer Configuration
 └ Policies
    └ Administrative Templates
       └ System
          └ Removable Storage Access

    Richtlinie:

    Removable Disks: Deny read access

    und

    Removable Disks: Deny write access

    Status:

    Enabled

    Teste die Wirkung auf <INT>-PC01.

    Teil 6 – GPO für eine bestimmte Abteilung

    Die IT-Abteilung benötigt Zugriff auf die Eingabeaufforderung, während diese für andere Benutzer weiterhin gesperrt bleiben soll.

    Alle IT-Benutzer müssen sich in der OU IT befinden.

    Erstelle ein neues Gruppenrichtlinienobjekt:

    IT_CMD_Allow

    Verknüpfe das GPO mit der OU:

    TechSolutions
 └─ Benutzer
     └─ IT

    Navigiere zu:

    User Configuration
 └ Policies
    └ Administrative Templates
       └ System

    Konfiguriere die Richtlinie:

    Prevent access to the command prompt

    auf

    Disabled

    Melde dich mit einem Benutzer aus der OU IT an und überprüfe, ob die Eingabeaufforderung gestartet werden kann.

    Melde dich anschließend mit einem Benutzer aus der OU Vertrieb oder Verwaltung an und überprüfe, ob die Eingabeaufforderung weiterhin gesperrt ist.

    Alternativ kann das auch über das Feature "Security Filtering" umgesetzt werden.

    Teil 7 – Gruppenrichtlinien aktualisieren

    Melde dich auf PC01 an.

    Führe aus:

    gpupdate /force

    Prüfe anschließend:

    gpresult /r

    Dokumentiere:

    • angewendete Benutzer-GPOs
    • angewendete Computer-GPOs

    Verwende folgende Werkzeuge:

    Group Policy Management
Group Policy Results Wizard

    • welche Richtlinien angewendet wurden
    • warum Richtlinien angewendet wurden
    • auf welche Benutzer und Computer sie wirken

    Teil 8 – Password Policy

    Öffne die Gruppenrichtlinienverwaltung:

    Group Policy Management
→ Forest
→ Domains
→ nachname.local
→ Default Domain Policy

    Bearbeite die Default Domain Policy.

    Navigiere zu:

    Computer Configuration
 └ Policies
    └ Windows Settings
       └ Security Settings
          └ Account Policies
             └ Password Policy

    Konfiguriere folgende Einstellungen:

    Minimum password length
→ 10 Zeichen

    Password must meet complexity requirements
→ Enabled

    Navigiere zu:

    Account Lockout Policy

    Konfiguriere:

    Account lockout threshold
→ 5 ungültige Anmeldeversuche

    Aktualisiere anschließend die Richtlinien:

    gpupdate /force

    Überprüfe:

    • Wird ein Kennwort mit weniger als 10 Zeichen akzeptiert?
    • Werden einfache Kennwörter abgelehnt?
    • Wird ein Konto nach mehreren ungültigen Anmeldeversuchen gesperrt?

    Teil 9 – Drive Mapping

    Voraussetzung: Der Fileserver -FS01 aus der Übung "Windows Enterprise Umgebung" muss vorhanden sein. Die Freigaben Allgemein, IT, Vertrieb und Verwaltung müssen erreichbar sein.

    Jede Abteilung erhält eine eigene Freigabe auf dem Fileserver.

    Auf <INT>-FS01 existieren bereits die Freigaben:

    \\<INT>-FS01\IT
\\<INT>-FS01\Vertrieb
\\<INT>-FS01\Verwaltung

    Verknüpfe ein neues GPO mit der OU:

    TechSolutions
 └ Benutzer
    └ IT

    Name:

    IT_Drive_Mapping

    Netzlaufwerk konfigurieren

    Navigiere zu:

    User Configuration
 └ Preferences
    └ Windows Settings
       └ Drive Maps

    Erstelle ein neues Netzlaufwerk.

    Konfiguration:

    Action: Create
Location: \\FS01\IT
Drive Letter: I:
Label: IT-Abteilung

    Weitere Abteilungen

    Erstelle entsprechende GPOs für:

    Vertrieb

    und

    Verwaltung

    mit passenden Laufwerksbuchstaben.

    Melde dich mit Benutzern verschiedener Abteilungen an.

    Überprüfe:

    • Werden die Laufwerke automatisch verbunden?
    • Erhält jede Abteilung ausschließlich ihr eigenes Laufwerk?

    Teil 10 – Windows Updates zentral verwalten

    Enabled

    Windows Update for Business

    Windows Update
 └ Windows Update for Business

    Konfiguriere:

    Qualitätsupdates

    Select when Quality Updates are received
Enabled
7 Tage Aufschub

    Funktionsupdates

    Select when Feature Updates are received
Enabled
30 Tage Aufschub

    Überprüfe auf <INT>-PC01:

    Windows Einstellungen
→ Windows Update

    Teil 10 – Zentrale Überwachung mit Zabbix

    In Unternehmen reicht es nicht aus, Server und Clients lediglich zu installieren und zu konfigurieren. Administratoren müssen jederzeit den Zustand ihrer Systeme überwachen können, um Ausfälle frühzeitig zu erkennen und schnell darauf zu reagieren.

    In dieser Aufgabe wird die bestehende Windows-Domänenumgebung um eine zentrale Monitoring-Lösung erweitert. Dazu wird ein bereits vorhandener Ubuntu-Server aus einer vorherigen Übung verwendet, auf dem Zabbix installiert ist. Zabbix ist ein Open-Source-Monitoringsystem zur Überwachung von Servern, Clients, Diensten und Netzwerkkomponenten. Es ermöglicht die zentrale Erfassung von Leistungsdaten, Verfügbarkeiten und Warnmeldungen.

    Melde dich an der vorhandenen Zabbix-Weboberfläche an.

    https://<IP-Adresse-des-Zabbix-Servers>/zabbix

    Nach der ersten Anmeldung:

    1. Ändere das Standardpasswort des Administrators.
    2. Dokumentiere die neue Konfiguration.
    3. Notiere die IP-Adresse des Zabbix-Servers.

    Agent auf <INT>-DC01

    Installiere den aktuellen Zabbix Agent für Windows auf <INT>-DC01

    Download:

    https://www.zabbix.com/download_agents

    Während der Installation trage die IP-Adresse des Ubuntu-Zabbix-Servers ein.

    Kontrolliere nach der Installation:

    Zabbix Agent

    im Windows-Dienstemanager.

    Der Dienst muss ausgeführt werden.

    Agent auf weiteren Endgeräte

    Installiere den Agenten zusätzlich auf dem Fileserver und dem Client.

    Hosts in Zabbix anlegen

    Öffne im Zabbix Dashboard:

    Data Collection
→ Hosts
→ Create Host

    Füge die zu überwachenden Geräte hinzu.

    Wähle als Template:

    Windows by Zabbix Agent

    Datenübertragung prüfen

    Warte einige Minuten.

    Kontrolliere anschließend:

    Monitoring
→ Hosts

    Die Hosts sollen als:

    Available

    angezeigt werden.

    Überwachung analysieren

    Öffne die Detailansicht von <INT>-DC01.

    Untersuche folgende Werte:

    • CPU Usage
    • Memory Utilization
    • Disk Usage
    • Network Traffic
    • Agent Availability

    Dokumentiere alle Messwerte mit Screenshots.

    Fragestellungen

    • Was ist ein Group Policy Object (GPO)?
    • Welche Vorteile bieten Gruppenrichtlinien in Unternehmensnetzwerken?
    • Welche Unterschiede gibt es zwischen Benutzer- und Computerkonfigurationen?
    • Warum werden GPOs in Active Directory gespeichert?
    • Warum werden GPOs häufig auf OUs und nicht direkt auf einzelne Benutzer angewendet?
    • Welche Vorteile bietet eine saubere OU-Struktur?
    • Welche Rolle spielen Sicherheitsgruppen bei der Anwendung von GPOs?
    • Was versteht man unter der Vererbung von Gruppenrichtlinien?
    • In welcher Reihenfolge werden Gruppenrichtlinien verarbeitet?
    • Was passiert, wenn mehrere GPOs dieselbe Einstellung konfigurieren?
    • Welche Vorteile hat ein zentral konfigurierter Desktophintergrund?
    • Warum sperren Unternehmen häufig die Systemsteuerung oder die Eingabeaufforderung?
    • Weshalb werden USB-Speichergeräte in vielen Unternehmen eingeschränkt?
    • Welche Einstellungen würdest du in einem Schulungsraum zusätzlich per GPO verwalten?

    Abgabe

    Die durchgeführten Tätigkeiten und gewünschten Elemente müssen in einem Protokoll zusammengefasst werden.

    Die Fragestellungen sollen ebenfalls in diesem Dokument bearbeitet werden.

    Das Protokoll ist eingescannt als ein PDF File zusammen mit einem evt. vorhandenem Projektfile auf moodle abzugeben.

    Verpflichtender Bestandteil des Protokolls und Basis für das Abgabegespräch ist eine eigenhändig erstellte Handskizze. Diese muss alle für die Aufgabe relevanten Elemente und Parameter enthalten und die wesentlichen Zusammenhänge der Lösung veranschaulichen.

    Ergänzende Hinweise zum Protokoll:

    • Übersicht aller erstellten GPOs
    • Zuordnung der GPOs zu OUs
    • Screenshots der wichtigsten Richtlinieneinstellungen
    • Nachweis des Desktophintergrunds
    • Nachweis der gesperrten Systemsteuerung
    • Nachweis der gesperrten Eingabeaufforderung
    • Nachweis der USB-Sperre
