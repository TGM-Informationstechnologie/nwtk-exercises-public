    Cisco Packet Tracer: Erstes Netzwerk mit 2 PCs

    Lernziele und Kompetenzen

    • die Benutzeroberfläche von Cisco Packet Tracer bedienen
    • Endgeräte in eine Topologie einfügen
    • Geräte mit dem passenden Netzwerkmedium verbinden
    • IPv4-Adressen und Subnetzmasken konfigurieren
    • die Netzwerkkonnektivität mittels Ping überprüfen
    • den Zusammenhang zwischen IP-Adresse, Subnetzmaske und Kommunikation erklären

    Voraussetzungen

    • Installierter Cisco Packet Tracer
    • Grundkenntnisse über IP-Adressen

    Aufgabenbeschreibung

    In dieser Übung erstellest du eine erste funktionsfähige Netzwerkverbindung mit Cisco Packet Tracer. Dabei werden zwei PCs direkt miteinander verbunden, mit IPv4-Adressen konfiguriert und anschließend auf Konnektivität getestet.

    Teil 1 – Geräte auswählen

    1. Starte Cisco Packet Tracer.
    2. Wähle im unteren Gerätebereich die Kategorie End Devices aus.
    3. Ziehe zwei PCs auf die Arbeitsfläche.
    4. Die Geräte erscheinen automatisch als:
    5. PC0
    6. PC1

    Teil 2 – Geräte verbinden

    Variante A – Manuelle Kabelauswahl

    1. Klicke auf Connections (Blitzsymbol).
    2. Wähle das Kabel Copper Cross-Over aus.
    3. Klicke auf PC0.
    4. Wähle die Schnittstelle FastEthernet0.
    5. Klicke anschließend auf PC1.
    6. Wähle ebenfalls FastEthernet0.

    Variante B – Automatische Kabelauswahl

    Alternativ kann die Funktion Automatically Choose Connection Type verwendet werden. Packet Tracer erkennt dabei automatisch den geeigneten Kabeltyp.

    Beobachtung

    Nach dem Verbinden erscheinen Statusanzeigen an den Ports.

    Beantworte:

    • Welche Farben werden an den Verbindungen angezeigt?
    • Was bedeuten diese Farben?
    • Wie lange dauert es, bis die Verbindung aktiv wird?

    Teil 3 – IP-Adressen konfigurieren

    PC0 konfigurieren

    1. Doppelklick auf PC0.
    2. Wechsel auf Config.
    3. Wähle FastEthernet0.
    4. Trage folgende Werte ein:
    IP-Adresse: 192.168.<KN>.1
Subnetzmaske: 255.255.255.0

    PC1 konfigurieren

    gleiches Vorgehen bei PC1

    IP-Adresse: 192.168.<KN>.2
Subnetzmaske: 255.255.255.0

    Diese Adressen befinden sich im selben Netzwerk 192.168.0.0/24 und ermöglichen daher die direkte Kommunikation beider Geräte.

    Teil 4a – Netzwerkkonnektivität testen

    Test von PC0 zu PC1

    1. Öffne PC0.
    2. Wechsel auf Desktop.
    3. Öffne den Command Prompt.
    4. Führe folgenden Befehl aus:
    ping 192.168.<KN>.2

    Test von PC1 zu PC0

    genauso umgekehrt

    ping 192.168.<KN>.1

    Dokumentieren Sie:

    • Anzahl der gesendeten Pakete
    • Anzahl der empfangenen Pakete
    • Paketverlust in %
    • Antwortzeit in ms

    Ein erfolgreicher Test bestätigt die korrekte Konfiguration der Netzwerkverbindung.

    Teil 4b – Verbindungstest mit Simple PDU

    Neben dem Ping über die Kommandozeile bietet Cisco Packet Tracer die Möglichkeit, die Kommunikation grafisch zu testen.

    Durchführung

    1. Wähle in der Werkzeugleiste das Symbol Add Simple PDU (Briefumschlag-Symbol) aus.
    2. Klicke zuerst auf PC0 als Quelle.
    3. Klicke anschließend auf PC1 als Ziel.

    Packet Tracer erzeugt nun automatisch ein ICMP-Paket (Ping) und simuliert die Übertragung zwischen beiden Geräten.

    Beobachten Sie die angezeigten Symbole und Verbindungsstatus:

    • Grüner Haken = Übertragung erfolgreich
    • Rotes Kreuz = Übertragung fehlgeschlagen

    Zusätzliche Informationen können über die Event List im unteren Bereich des Simulationsfensters eingesehen werden.

    Teil 4c – Simulationsmodus

    1. Wechsel von Realtime zu Simulation.
    2. Erstelle erneut eine Simple PDU.
    3. Verwende Capture / Forward, um die einzelnen Schritte der Paketübertragung zu verfolgen.

    Dokumentieren Sie:

    • Welche Protokolle angezeigt werden.
    • Welche Ereignisse in der Event List erscheinen.

    Teil 5 – ARP-Tabelle untersuchen

    Bevor zwei Geräte miteinander kommunizieren können, müssen sie die MAC-Adresse ihres Kommunikationspartners kennen. Dafür wird das Protokoll ARP (Address Resolution Protocol) verwendet.

    Schritt 1 – ARP-Tabelle vor dem Ping prüfen

    PC0

    Wechsel auf Desktop → Command Prompt und zeige die aktuelle ARP-Tabelle an:

    arp -a

    Lösche alle vorhandenen Einträge:

    arp -d *

    Kontrolliere das Ergebnis:

    arp -a

    PC1

    Führe dieselben Schritte durch.

    Die ARP-Tabelle sollte nun leer sein oder deutlich weniger Einträge enthalten.

    Beantworte folgende Frage: Warum ist es für dieses Experiment sinnvoll, die ARP-Tabelle vor dem Kommunikationstest zu löschen?

    Ersten Ping durchführen

    Öffne auf PC0 die Eingabeaufforderung und führe aus:

    ping 192.168.0.2

    Beobachte den ersten Ping-Durchlauf im Simulationsmodus und analysiere jeden einzelnen Schritt.

    • Warum dauert die erste Antwort häufig länger als die nachfolgenden?
    • Welche zusätzlichen Netzwerkvorgänge finden vor dem eigentlichen ICMP-Ping statt?

    ARP-Tabelle nach dem Ping untersuchen

    Zeigen Sie erneut die ARP-Tabelle an:

    arp -a

    Nun sollte ein dynamischer Eintrag für den Kommunikationspartner vorhanden sein.

    Beispiel:

    Internet Address      Physical Address      Type
192.168.0.2           xx-xx-xx-xx-xx-xx     dynamic

    Die MAC-Adresse kann je nach Packet-Tracer-Datei unterschiedlich sein.

    Beschreibe:

    1. Welche neue Information wurde in der ARP-Tabelle gespeichert?
    2. Warum ist diese Information für die Ethernet-Kommunikation notwendig?
    3. Was würde passieren, wenn die ARP-Tabelle erneut gelöscht wird?

    Teil 6 – Fehlersuche

    Führe nun einen Fehler absichtlich herbei.

    Ändern Sie die IP-Adresse von PC1 auf:

    192.168.<KN>+1.2

    Prüfen Sie erneut die Verbindung.

    Beantworte:

    1. Ist der Ping erfolgreich?
    2. Warum funktioniert die Kommunikation nicht mehr?
    3. Welche Einstellung muss korrigiert werden?

    Stellen Sie anschließend die korrekte Konfiguration wieder her.

    Teil 7 – Reflexion

    Beantworten Sie die folgenden Fragen:

    1. Warum benötigen beide PCs eine eindeutige IP-Adresse?
    2. Welche Funktion hat die Subnetzmaske?
    3. Wann wird ein Cross-Over-Kabel verwendet?
    4. Welche Informationen liefert der Ping-Befehl?
    5. Warum können Geräte mit unterschiedlichen Netzwerken nicht direkt kommunizieren?
