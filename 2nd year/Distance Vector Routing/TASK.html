    Distance Vector Routing am Beispiel RIP

    Einführung

    Das Routing Information Protocol (RIP) ist ein Distance-Vector-Routingprotokoll, das zur automatischen Pflege von Routingtabellen in IP-Netzwerken verwendet wird. Router tauschen dabei regelmäßig Informationen über erreichbare Netzwerke aus und berechnen auf Basis der Anzahl der Hops (Hop Count) den besten Pfad zu einem Ziel.

    RIP gehört zu den ältesten Routingprotokollen und eignet sich besonders für kleinere und überschaubare Netzwerke. In dieser Übung lernst du die Konfiguration von RIPv2, die Bedeutung von Routing-Updates sowie die Auswirkungen der automatischen Routenzusammenfassung kennen.

    Ziele

    • Dynamisches Routing mit RIP konfigurieren
    • Routingtabellen analysieren und interpretieren
    • RIPv2 von RIPv1 unterscheiden
    • Passive Interfaces sinnvoll einsetzen
    • Standardrouten mit RIP verteilen
    • Fehlerquellen bei Distance-Vector-Protokollen analysieren

    Kompetenzzuordnung

    NWTK Switching und Routing

    • grundlegende Routingaufgaben erklären und in kleinen Netzwerken statisches Routing einsetzen

    Voraussetzungen

    • Packet Tracer installiert
    • Turorial zur Cisco Router Comman Line durchgearbeitet: Understand the Command Line Interface (CLI) - OpenClassrooms
    • Grundkenntnisse zu statischem Routing vorhanden

    Detaillierte Aufgabenbeschreibung

    Wir betrachten die vorgegebene Netzwerktopologie.

    Die Adressierung erfolgt gemäß der vorgegebenen Tabelle und basiert auf deiner Katalognummer.

    Gerät Schnittstelle IP Subnetmaske
    R1 G0/1 172.(KN).10.1 255.255.255.0
    R1 S0/0/0 10.(round(KN/3).1.1 255.255.255.252
    R2 G0/0 209.(KN*3).201.1 255.255.255.0
    R2 S0/0/0 10.(round(KN/3).1.2 255.255.255.252
    R2 S0/0/1 10.(round(KN/3)+1).2.2 255.255.255.252
    R3 G0/1 172.(Katalognummer).30.1 255.255.255.0
    R3 S0/0/1 10.(round(KN/3)+1).2.1 255.255.255.252
    PC-A NIC 172.(KN).10.3 255.255.255.0
    PC-B NIC 209.(KN*3).201.2 255.255.255.0
    PC-C NIC 172.(KN).30.3 255.255.255.0

    Ergänzung für serielle Verbindungen

    Verwende für alle seriellen Verbindungen folgende Bandbreite:

    interface s<id>
 clock rate 1544000
 bandwidth 1544

    Dies entspricht einer klassischen T1-Strecke mit 1,544 Mbit/s.

    clock rate 1544000

    • Legt die tatsächliche Taktrate der seriellen Verbindung fest.
    • Muss nur auf der DCE-Seite konfiguriert werden.
    • Entspricht einer T1-Leitung mit 1,544 Mbit/s.

    bandwidth 1544 (schon als Vorarbeit für Link-State Protokolle wie OSPF relevant)

    • Informiert Routingprotokolle über die verfügbare Bandbreite.
    • Verändert die tatsächliche Übertragungsgeschwindigkeit nicht.
    • Wird von Protokollen wie OSPF oder EIGRP zur Metrikberechnung verwendet.

    Hinweis: Die Einstellung der Bandbreite dient in dieser Übung ausschließlich zur Information für Routingprotokolle. RIP verwendet jedoch ausschließlich den Hop Count als Metrik und berücksichtigt die konfigurierte Bandbreite nicht bei der Routenwahl.

    Aufgabe Grundkompetenz:

    GUI vs CLI

    In dieser Übung wird sowohl die grafische Benutzeroberfläche (GUI) als auch die Kommandozeile (CLI) verwendet.

    Wenn du die Zeile bisher in den Voraussetzungen ignoriert hast, dann ist jetzt der richtige Zeitpunkt für das Tutorial: Understand the Command Line Interface (CLI) - OpenClassrooms.

    Über die GUI werden die Topologie aufgebaut, Geräte verbunden und die PCs konfiguriert.

    Die Konfiguration der Router kann grundsätzlich ebenfalls über die GUI erfolgen, wird in dieser Übung jedoch über die CLI durchgeführt. Dazu gehören die Vergabe von IP-Adressen, das Aktivieren von Interfaces, das Konfigurieren von Clock Rate und Bandwidth auf seriellen Verbindungen, die Einrichtung von RIPv2, die Konfiguration von Standardrouten sowie die Analyse der Routingtabellen.

    Ping-Tests können sowohl über die Eingabeaufforderung der PCs als auch über die CLI der Router durchgeführt werden. Nach erfolgreicher Überprüfung der Konnektivität sind sowohl die Routerkonfigurationen als auch die Packet-Tracer-Datei dauerhaft zu speichern.

    Router> <– User EXEC Mode
Router# <– Privileged EXEC mode
Router(config)# <– Global Configuration Mode
Router(config-if)# <– Interface Configuration Mode
Router(config-line)# <– Line Configuration Mode

    Bevor es an die Übung geht, noch ein wichtiger Einschub zur Fehlersuche.

    Vorgehensweise bei Ping-Tests

    Bei der Fehlersuche in Netzwerken sollte systematisch vorgegangen werden. Beginne immer mit kurzen Verbindungen und erweitere die Tests schrittweise auf größere Entfernungen. So lässt sich ein Fehler schneller eingrenzen.

    Schritt 1: Eigenes Netzwerk prüfen

    Teste zuerst die Geräte im eigenen Netzwerk.

    PC-A → eigenes Gateway (R1)

    PC-B → eigenes Gateway (R2)

    PC-C → eigenes Gateway (R3)

    Wenn dieser Test fehlschlägt, liegt das Problem meist bei:

    • IP-Adresse
    • Subnetzmaske
    • Default Gateway
    • Verkabelung
    • Interface-Status

    Schritt 2: Direkte Nachbarn prüfen

    Teste anschließend die direkt verbundenen Router.

    R1 ↔ R2

    R2 ↔ R3

    Hier wird überprüft, ob die Punkt-zu-Punkt-Verbindungen korrekt funktionieren.

    Schritt 3: Entfernte Netzwerke prüfen

    Erst wenn die lokalen Verbindungen funktionieren, werden weiter entfernte Ziele getestet.

    PC-A → PC-B

    PC-A → PC-C

    PC-C → PC-B

    Diese Tests überprüfen:

    • Routingtabellen
    • RIP-Konfiguration
    • Routing-Updates
    • Erreichbarkeit über mehrere Router

    Schritt 4: Standardroute prüfen

    Zum Schluss werden Ziele getestet, die über die verteilte Default Route erreichbar sein sollen.

    Beispiel:

    PC-A → 209.(KN*3).201.2

    PC-C → 209.(KN*3).201.2

    für diese und alle weiteren Übungen: Eigenes Gateway → Nachbarrouter → entfernte Netzwerke → Internetziel

    Teil 1 – Aufbauen des Netzwerks

    1. Erstelle die Topologie in Packet Tracer.
    2. Konfiguriere alle Router-Interfaces gemäß der vorgegebenen Adresstabelle.
    3. Konfiguriere die PCs.
    4. Überprüfe die lokale Erreichbarkeit mittels Ping.

    Teil 2 – Konfigurieren von RIPv2

    Konfiguriere auf allen Routern RIPv2.

    Aktiviere RIP Version 2.

    version 2

    Füge alle direkt angeschlossenen Netzwerke hinzu.

    network <netzwerkadresse>

    Das Netzwerk

    209.(Katalognummer*3).201.0/24

    darf nicht angekündigt werden.

    Verwende auf LAN-Schnittstellen den Befehl:

    passive-interface

    um unnötige Routing-Updates zu vermeiden.

    Der Befehl weist die angegebene Schnittstelle an, keine Routing-Updates zu senden. Auf diese Weise kann unnötiger Routing-Datenverkehr im LAN vermieden werden. Das Netzwerk, zu dem die angegebene Schnittstelle gehört, wird jedoch weiterhin in Routing-Updates angekündigt, die über andere Schnittstellen gesendet werden.

    Dokumentiere anschließend:

    show ip protocols

    Teil 3 – Analyse der Routingtabellen

    Führe auf allen Routern folgende Befehle aus:

    show ip route
show ip interface brief

    Beantworte folgende Fragen:

    1. Kann PC-A PC-B erreichen? Warum?
    2. Kann PC-A PC-C erreichen? Warum?
    3. Kann PC-C PC-B erreichen? Warum?
    4. Kann PC-C PC-A erreichen? Warum?
    5. Welche RIP-Einträge erscheinen in der Routingtabelle?
    6. Welche Netze wurden dynamisch gelernt?

    Dokumentiere deine Beobachtungen.

    Teil 4 – RIP analysieren

    Verwende die folgenden Befehle:

    debug ip rip
show ip protocols
show running-config

    Beschreibe für jeden Befehl:

    • Welche Informationen werden angezeigt?
    • Wozu dient der Befehl?
    • Welche Informationen zu RIP können daraus gewonnen werden?

    Beende die Analyse anschließend mit:

    undebug all

    Teil 5 – Automatische Zusammenfassung deaktivieren

    RIPv2 unterstützt klasslose Netzwerke. Standardmäßig werden jedoch Netzwerke an Klassen-Grenzen zusammengefasst.

    Deaktiviere deshalb auf allen Routern:

    no auto-summary

    Danach um die Routing-Tabelle auf allen Routern löschen:

    clear ip route *

    Vergleiche die Routingtabellen vor und nach der Änderung.

    Beantworte:

    1. Welche Einträge haben sich verändert?
    2. Welche zusätzlichen Informationen stehen nun zur Verfügung?
    3. Warum ist die Abschaltung von Auto-Summary in modernen Netzwerken häufig notwendig?
    4. Wie verändern sich die Ergebnisse der Ping-Tests?

    Teil 6 – Standardroute verteilen

    Damit die übrigen Router einen Weg ins „Internet“ kennen, wird auf R2 eine Standardroute eingerichtet.

    R2(config)# ip route 0.0.0.0 0.0.0.0 209.(KN*3).201.2

    Anschließend wird diese Route über RIP verteilt:

    R2(config)# router rip
R2(config-router)# default-information originate

    Untersuche mit:

    show ip route
    • Woran erkennst du die gelernte Standardroute?
    • Welchen nächstgelegenen Router verwenden R1 und R3 für unbekannte Ziele?
    • Welche Kennzeichnung besitzt die Default Route in der Routingtabelle?

    Teil 7 – Konnektivität überprüfen

    Vergewissern dich, dass die Hosts in dem in Subnetze untergliederten Netzwerk einander erreichen können, indem du Pings zwischen PCs in verchiedenen Netzen sendest.

    • PC-A und PC-B
    • PC-A und PC-C
    • PC-C und PC-B
    • PC-C und PC-A

    Zusätzlich sende Pings von PC-A und PC-C, um Datenübertragungen in das Internet zu simulieren

    ping zu 209.(KN*3).201.2

    Beispiel für R1

    Die folgenden Befehle müssen über die CLI eingegeben werden.

    R1>enable
R1#>config t
R1(config)# router rip
R1(config-router)# version 2
R1(config-router)# passive-interface g0/1
R1(config-router)# network 172.30.0.0
R1(config-router)# network 10.0.0.0
R1(config-router)# no auto-summary
R1(config-router)# end
R1# clear ip route *
R1# show ip route
R1# show ip protocols
R1# show ip interface brief
R1# debug ip rip
...

    Teil 8 – Zusätzliche Verbindung

    Ergänze eine direkte Verbindung zwischen R1 und R3.

    Vorgabe:

    • Bandbreite deutlich höher als die bestehenden seriellen Verbindungen, verwende z.B. ein Fast Ethernet oder Gigabit Ethernet Interface (du kannst auch alternativ eine serielle Verbindung mit höherer Clockrate clock rate 10000000 und Bandbreite bandwidth 10000 nutzen.
    • Überlege dir selbständig eine Addressierung.
    • RIP soll die neue Verbindung automatisch berücksichtigen

    Analyse:

    1. Wie verändert sich die Routingtabelle?
    2. Welche Pfade werden bevorzugt?
    3. Welche Metrik verwendet RIP?
    4. Welche Rolle spielt die tatsächliche Bandbreite bei RIP?
    5. Was passiert, wenn die Verbindung zwischen R2 und R3 ausfällt?
    6. Wie lange benötigt RIP ungefähr zur Anpassung?

    Teil 8 – Ausfall einer Verbindung analysieren

    Schalte die serielle Verbindung zwischen R2 und R3 ab.

    interface s0/0/1
shutdown
    1. Welche Routen verschwinden aus der Routingtabelle?
    2. Wie lange dauert es, bis RIP die Änderung erkannt hat?
    3. Sind PC-A und PC-C weiterhin erreichbar?
    4. Was passiert mit Ping-Anfragen während der Umstellung?
    5. Welche RIP-Mechanismen sorgen dafür, dass die Routingtabellen aktualisiert werden?

    Teil 9 – RIP und Sicherheit

    Recherchiere die Authentifizierung von RIPv2.

    1. Erkläre den Unterschied zwischen Routing-Protokollen mit und ohne Authentifizierung.
    2. Recherchiere Plain-Text- und MD5-Authentifizierung.
    3. Beschreibe mögliche Angriffe auf RIP.
