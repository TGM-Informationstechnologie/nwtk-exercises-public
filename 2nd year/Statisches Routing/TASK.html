    Statisches Routing

    Einführung

    In größeren Netzwerken müssen Router entscheiden, über welchen Weg Datenpakete zu ihrem Ziel gelangen. Eine Möglichkeit dazu ist das statische Routing. Dabei werden die notwendigen Routen von der Netzwerkadministratorin bzw. vom Netzwerkadministrator manuell konfiguriert.

    Statische Routen werden nicht automatisch durch Routingprotokolle gelernt. Dadurch sind sie einfach, ressourcenschonend und gut nachvollziehbar. Allerdings müssen Änderungen der Netzwerktopologie ebenfalls manuell nachgeführt werden.

    In dieser Übung planst du die IP-Adressierung eines Unternehmensnetzwerks, entwickelst die Routingtabellen und setzt die Konfiguration in Packet Tracer um.

    Ziele

    • Statische Routen anhand einer gegebenen Netztopologie erstellen
    • Default-Routen sinnvoll einsetzen
    • Routingtabellen analysieren und interpretieren
    • Die Erreichbarkeit von Netzwerken mit geeigneten Werkzeugen überprüfen

    Kompetenzzuordnung

    NWTK Switching und Routing

    • grundlegende Routingaufgaben erklären und in kleinen Netzwerken statisches Routing einsetzen

    NWTK Adressierung

    • asymmetrische Adressierungen berechnen und in größeren Netzwerken einsetzen (IPv4, IPv6)

    Voraussetzungen

    • Packet Tracer installiert
    • Grundlagen des IPv4-Subnettings wiederholt
    • Grundlagen der Routerkonfiguration bekannt
    • Umgang mit den Befehlen ping, traceroute/tracert sowie show ip route

    Detaillierte Aufgabenbeschreibung

    Wir betrachten die Netztopologie des Unternehmens Innovate AG.

    Bei der Planung und Umsetzung sind folgende Vorgaben einzuhalten:

    1. Die Netze NET1, NET2 und NET3 müssen untereinander erreichbar sein.
    2. Alle internen Netze sollen Zugriff auf das Internet erhalten.
    3. Die Router R1 und R2 erhalten jeweils die höchste nutzbare Host-Adresse in ihren direkt angeschlossenen LAN-Netzen.
    4. Für die Verbindungen zwischen den Routern werden Punkt-zu-Punkt-Netze mit genau zwei nutzbaren Host-Adressen verwendet.
    5. Bei Router-zu-Router-Verbindungen erhält der Router mit der kleineren Nummer bzw. Bezeichnung die niedrigere Host-Adresse.
    6. Das öffentliche Interface ppp0 des Gateways G ist bereits mit dem Internet verbunden.
    7. Das Standardgateway des Routers G ist 93.221.23.1.

    Aufgabe Grundkompetenz:

    Auch wenn unten in der Angabe tw. Command Line Befehle gezeigt werden ist die Konfiguration weiterhin komplett aus der grafischen Oberfläche heraus möglich. Du kannst aber gerne anfangen auch schon CLI Befehle zu nutzen. Bei späteren Übungen wird das notwendig sein. Cheet Sheets dazu findest du im Kurs.

    Teil 1 – Adressierung

    Analysiere die vorgegebene Topologie und bestimme für jedes dargestellte Netzwerk:

    • Netzwerkadresse
    • Subnetzmaske bzw. Präfix
    • erste nutzbare Host-Adresse
    • letzte nutzbare Host-Adresse
    • Broadcast-Adresse

    Weise allen Router-Interfaces passende IPv4-Adressen zu.

    Überarbeite die Topologie indem du sämtliche Adressen einträgst.

    Teil 2 – Routingtabellen erstellen

    Ermittle für jeden Router die direkt angeschlossenen Netzwerke.

    Erarbeite die statischen Routen für:

    • Router R1
    • Router R2
    • Gateway G

    Überlege, an welchen Stellen eine Default Route eingesetzt werden kann und reduziere dadurch die Anzahl der erforderlichen statischen Einträge soweit wie möglich.

    Nutzen Sie auch eine Default Route für den Zugang zum Internet.

    Teil 3 – Implementierung in Packet Tracer

    • Erstelle die Topologie in Packet Tracer.
    • Konfiguriere alle Interfaces.
    • Konfiguriere die statischen Routen.
    • Konfiguriere die Default-Routen.
    • Richte den HTTP-Server ein.
    • Speichere die Konfiguration aller Geräte.

    Da Packet Tracer keinen direkten Internetzugang bereitstellt, wird in dieser Übung die "Internet Cloud" durch einen Router ISP und einen Webserver WEB ersetzt.

    Der Router ISP simuliert einen Internetprovider.

    G (ppp0)    93.221.23.2/30
ISP (WAN)   93.221.23.1/30
ISP (WEB)   203.0.113.1/24
WEB         203.0.113.10/24

    Konfiguriere einen Webserver in Packet Tracer mit:

    • IPv4-Adresse gemäß Adressierungsschema
    • passendem Gateway
    • aktiviertem HTTP-Dienst

    Hinweise zum Routing:

    Auf Router G ist eine Default Route zum ISP zu konfigurieren:

    ip route 0.0.0.0 0.0.0.0 93.221.23.1

    Der ISP soll sämtliche unbekannten Ziele über das Unternehmensgateway erreichen:

    ip route 0.0.0.0 0.0.0.0 93.221.23.2

    Für diese Übung wird bewusst kein NAT eingesetzt. Die Erreichbarkeit wird ausschließlich durch Routing sichergestellt.

    Teil 4 – Überprüfung der Konfiguration

    Dokumentiere den Output von:

    show ip route

    Als Alternative bietet Packet Tracer auch die Möglichkeit über die GUI (Rechte Maustaste auf Gerät) die Routing Tabelle darzustellen.

    Teste mittels ping:

    • NET1 → NET2
    • NET1 → NET3
    • NET2 → NET3
    • alle Netze → Gateway G
    • alle Netze → Webserver

    Verwende für mindestens einen Test traceroute/tracert:

    auf PCs:

    tracert <IP-Adresse des Webservers>

    auf Routern:

    traceroute <IP-Adresse des W

    Öffne von mindestens einem Client in jedem Netz den Webbrowser und rufe die Webseite des Servers auf:

    http://203.0.113.10

    Dokumentiere den erfolgreichen Zugriff von:

    • Client in NET1
    • Client in NET2
    • Client in NET3

    Aufgabe Erweiterte Kompetenz:

    Die Topologie mit MPLS- und T1-Verbindungen dient in erster Linie der Analyse von Routingentscheidungen und Backup-Routen. Die vollständige praktische Umsetzung in Packet Tracer ist deutlich aufwändiger als die Grundaufgabe.

    Damit die Kommunikation zwischen den Standorten funktioniert, muss nicht nur der Hinweg, sondern auch der Rückweg (Retourroute) korrekt konfiguriert sein. Jede Route, die ein Router kennt, muss auf der Gegenseite ebenfalls berücksichtigt werden.

    Die erweiterte Aufgabe muss nicht vollständig in Packet Tracer aufgebaut werden. Der Schwerpunkt liegt auf:

    • der Planung des VLSM-Adressierungsschemas,
    • der Analyse von MPLS- und T1-Verbindungen,
    • dem Verständnis von Administrative Distance,
    • dem Entwurf von Floating Static Routes,
    • der Begründung von Routingentscheidungen.

    Teil 5 – Floating Static Route

    Gegeben ist die dargestellte Topologie mit MPLS- und T1-Verbindungen.

    Entwirf ein vollständiges VLSM-Adressierungsschema und dokumentiere:

    • Netzwerkadresse
    • Präfix
    • Anzahl benötigter Hosts
    • verwendeter Adressbereich

    Beantworte folgende Fragen:

    1. Welcher Link bietet die höhere Bandbreite?
    2. Welche Rolle spielt die Administrative Distance (AD)?
    3. Welche Route (MPLS/T1) wird bevorzugt, wenn:
    4. beide Routen statisch konfiguriert sind?
    5. eine Route dynamisch gelernt wurde?

    Recherchiere und erkläre:

    • Was ist eine Floating Static Route?
    • Warum wird sie verwendet?
    • Wie funktioniert die Administrative Distance als Prioritätsmechanismus?

    Konfiguriere anschließend eine Floating Static Route als Backup-Verbindung.

    Dokumentiere die verwendeten Befehle und Administrative-Distance-Werte.

    Fragestellungen

    Im Rahmen dieser Übung benantworte folgende Fragestellungen:

    Grundkompetenz

    • Was ist eine statische Route und wie unterscheidet sie sich von einer dynamischen Route?
    • Welche Informationen müssen bei der Konfiguration einer statischen Route angegeben werden?
    • In welchen Situationen ist der Einsatz statischer Routen sinnvoll?
    • Welche Vor- und Nachteile besitzen statische Routen?
    • Was passiert, wenn sich die Netzwerktopologie ändert und ausschließlich statische Routen verwendet werden?
    • Wie kann überprüft werden, ob eine statische Route korrekt funktioniert?
    • Was versteht man unter einer Default Route?
    • Welche Befehle können verwendet werden, um die Routingtabelle eines Routers anzuzeigen?
    • Warum werden für Router-zu-Router-Verbindungen häufig /30- oder /31-Netze verwendet?

    Erweitert

    • Wofür steht die Abkürzung MPLS?
    • Wie funktioniert die grundsätzliche Weiterleitung von Paketen in einem MPLS-Netz?
    • Für welche Anwendungen wird MPLS häufig eingesetzt?
    • Welche typischen Übertragungsgeschwindigkeiten werden bei MPLS-Anbindungen erreicht?
    • Was ist eine E1/T1-Leitung?
    • Welche Unterschiede bestehen zwischen MPLS und T1/E1 hinsichtlich Bandbreite, Kosten und Einsatzgebiet?
    • Was ist eine Floating Static Route?
    • Welche Funktion hat die Administrative Distance?
    • Was ist das europäische Pendant E1 und welche Datenrate bietet es?
    • Welche Vorteile bietet eine Backup-Verbindung für ein Unternehmensnetzwerk?

    Abgabe

    Die durchgeführten Tätigkeiten und gewünschten Elemente müssen in einem Protokoll zusammengefasst werden. Die Fragestellungen sollen ebenfalls in diesem Dokument bearbeitet werden.

    Das Protokoll ist eingescannt als ein PDF File zusammen mit dem Packet Tracer Projektfile auf moodle abzugeben.

    Ergänzende Hinweise zum Protokoll:

    • Ergänze die Routingtabellen aller Router!

    Befehlsüberblick

    Aufgabe Syntax Beispiel
    Privilegierten Modus aktivieren enable Router> enable
    Routingtabelle anzeigen show ip route Router# show ip route
    Statische Route anlegen ip route Zielnetz Subnetzmaske Next-Hop ip route 192.168.3.0 255.255.255.0 10.0.0.2
    Default Route anlegen ip route 0.0.0.0 0.0.0.0 Next-Hop ip route 0.0.0.0 0.0.0.0 93.221.23.1
    Floating Static Route (Backup) anlegen ip route Zielnetz Subnetzmaske Next-Hop AD ip route 192.168.4.0 255.255.255.0 10.0.1.2 10
    Route löschen no ip route Zielnetz Subnetzmaske Next-Hop no ip route 192.168.3.0 255.255.255.0 10.0.0.2
    Konfiguration speichern copy running-config startup-config Router# copy running-config startup-config
    Alternative zum Speichern write memory Router# write memory
